## 五、设计层面的缺陷和风险

### 🔴 阻塞级风险

#### 1. AOT `emit_call` 返回值类型硬编码 `i32`（#14, #32）

**根因**：`emit.rs:1039`
```rust
let ret_ty = "i32".to_string(); // 默认 i32
```

这是单行代码导致的系统性缺陷——所有函数调用（用户函数 + native 函数）的返回值都被假设为 `i32`。当 native 函数返回指针（`malloc`/`CString`/`Handle` 等）、浮点数、`void`、或任何非 `i32` 类型时，生成的 LLVM IR 类型不匹配，`llc` 编译失败。

**影响范围**：所有含 native 函数调用的 AOT 编译——标准库、FFI、并发函数、手动内存管理全部受影响。

#### 2. HIR 层丢弃核心技术特性（#1, #2, #3）

技术方案定义的以下核心特性在 HIR 层完全丢失：
- **枚举**（带关联值）→ `Decl::Enum => {}`（`hir.rs:347`）
- **闭包/高阶函数** → `__lambda` 占位符（`hir.rs:1181`）
- **函数类型** `(A) -> B` → `HirType` 无 `Function` 变体（`hir.rs:18-28`）

**影响**：AOT 和 VM 两种模式都无法支持方案中定义的枚举、闭包、高阶函数，而这些是技术方案 §3–§4 的核心内容。

#### 3. 并发运行时全部单线程（#8, #9, #10, #11, #12）

技术方案要求 M:N 线程模型，但所有并发设施都在单线程 VM 内执行：
- 协程调度器：简单 Vec 队列，无 OS 线程
- Actor 运行时：纯 struct，无 `Arc`/`Mutex`/线程
- `select`：轮询遍历所有通道
- Channel：无超时机制
- Actor 监督：无死亡传播

**影响**：`spawn()` 不是跨线程的，Actor 的"私有状态"没有并发保护，并发模型是假并发。

#### 4. VM/AOT 值模型不统一（#24, #29, #30）

三种值模型并存且互不兼容：
- **VM**：`Value` 枚举（10 变体，含 `Rc<str>`/`Vec`/`HashMap`，非线程安全）
- **LLVM AOT**：LLVM IR 类型系统（`{i8*, i64}` 等）
- **C AOT**：C 类型（`const char*`/`void*` 等）

同一份 Aura 代码在三种后端下类型表示不同，无统一桥接。

### 🟡 高风险

#### 5. JIT 与编译器优化策略冲突（#7）

JIT 白名单拒绝 `CallMethod`/`CallNative`/`CallC`/集合操作/对象操作/控制流等指令。这意味着：
- 含任何方法调用的函数 → 解释器
- 含 FFI 调用的函数 → 解释器
- 含集合操作的函数 → 解释器
- 含对象创建的函数 → 解释器

JIT 仅对纯整数计算叶子函数有效，对绝大部分实际代码无效。

#### 6. C ABI 蹦床 4 参数限制 + 全 i64 参数（#21, #22）

蹦床函数硬编码 4 个数据参数，超过的截断。静态链接将所有参数通过 `as_int()` 转为 i64，无论实际类型是 f64、指针还是结构体。这不是可靠的 C ABI 实现。

#### 7. 技术方案与实现脱节（#15, #16, #31）

技术方案第九章的整个设计（基于 inkwell API 的代码示例）与实际实现完全脱节。第九章代码示例无法运行。

#### 8. 默认全量 std 注册（#25）

虽然 `register_with_modules` 存在（`std/mod.rs:123`），但默认的 `NativeRegistry::new()` 调用 `register_all`，注册全部 ~396 个函数。按需加载能力已实现但未成为默认路径。

### 🟢 中风险

#### 9. 泄漏检测不完整（#20）

仅检查 MIR 层 Retain/Release 计数，不检测运行时堆泄漏、闭包捕获泄漏、malloc/free 配对。

#### 10. 文档覆盖不足（#26）

79 个文档条目 vs ~250+ 原生函数，~170 个函数无文档。

#### 11. 泛型单态化按 arity（#5）

`identity<Int>` 和 `identity<String>` 共享同一份 MIR，类型信息丢失。

#### 12. Await 静默 no-op（#13）

非 `suspend` 函数中 `await` 不报错，语义不正确。

## 七、建议修复优先级
