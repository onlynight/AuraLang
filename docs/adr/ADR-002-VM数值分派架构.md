# ADR-002：VM 数值分派架构（消除字符串 else-if 链）

- **状态**：已接受（2026-10-01）
- **关联**：VM-PA-00 v3.1 §2.2 / P0.4；ADR-001

## 背景

`Vm.aura` 的分派器是 125 条 `else if (opcode == "...")` 字符串线性比较（O(N) 分派，
每条指令平均 60+ 次字符串比较）。opcode 与参数虽已在加载期缓存（`lines`/`ops`/
`argCache`，见 `Vm.aura:53-59` 注释），但分派本身仍走字符串。

## 决策

1. **加载期一次转换**：`buildLineCache()` 在切行时同步把助记符经
   `Opcodes.fromName()` 转为数值编号，存入 `opCodes: List<Int>`（与 `ip` 对齐）。
   - 注释行（`#` 开头）与空行编号为 `OP_NOP`，执行循环直接跳过；
   - 未认知的助记符编号为 `OP_UNKNOWN`，执行到时以原始助记符（保留 `opNames`
     数组供诊断）报 `Unknown opcode`，与既有行为一致。
2. **执行期分派只做数值比较**：`dispatch(op: Int, args)` 的分支条件全部是
   `Opcodes.*` 数值常量，不再出现 `opcode == "..."` 字符串比较。
3. **跳转重定位**：文本字节码的 `JUMP*` 操作数在 Codegen 发射期已解析为行号，
   `.auc` 路径由 AucLoader 重扫译为行号——VM 加载期无需二次重定位，本决策将
   该约定固化为字节码契约。
4. **保留文本字节码作为 P0 输入兼容层**（VM-PA-00 R3 缓解措施）：`.aura` 文本
   模式与 `.auc` 翻译模式均先汇入文本行，再统一数值化；数值 `.auc` 直读
   （取消文本翻译）属 P2.2。

## 后果

- 分派从 O(N) 字符串比较降为 O(N) 整数比较；加载期一次性付 `fromName` 哈希成本。
- `opCodes`（Int）与 `opNames`（String，仅诊断用）并存，内存增量约每指令一个引用。
- 未知指令错误信息保持原样（含助记符），诊断体验不回退。
