# 03 · 分阶段开发计划（全域）

> **范围**：P0–P5 六个阶段，覆盖三种执行模式（VM/JIT/AOT），每阶段独立可开发、独立可验收、独立可回退
> **配套文档**：[02-技术方案.md](./02-技术方案.md)（设计）、[04-测试与验收矩阵.md](./04-测试与验收矩阵.md)（测试）、[05-风险与开放问题.md](./05-风险与开放问题.md)（风险）
> **总工期估算**：15–18 周（约 3.5–4.5 个月，单人全职），与 `docs/pure_aura/` 宏观路线并行
> **覆盖模式**：VM 解释器 + JIT（Cranelift）+ AOT（LLVM）
> **保留边界**：bootstrap + Cranelift + syscall 运行库（Rust 重写）+ AOT native 内容（均不修改）

---

## 一、阶段总览

```text
P0 ──→ P1 ──→ P2 ──→ P3 ──→ P4 ──→ P5
│      │      │      │      │      │
基础   AOT    JIT    Std    三模式  性能
契约   收尾   模式   +调试器 集成   基准
2 周   3 周   4 周   3 周   2 周   3 周
```

| 阶段 | 名称 | 计划工期 | 实际状态 | 调整工期 | 核心目标 |
|------|------|---------|---------|---------|---------|
| **P0** | 基础契约与测试框架 | 2 周 | TestRunner.aura 已有 | **0.5 周** | 验收脚本 + 不变量断言 |
| **P1** | AOT 模式收尾 | 3 周 | ✅ **100% 完成** | **0 周** | —（自举链已跑通） |
| **P2** | JIT 模式 | 4 周 | 纯 Aura 侧完成，FFI 边界未实现 | **4 周** | `jit_ffi.rs` + `VmJitBridge.aura` |
| **P3** | Std + 调试器 | 3 周 | 调试器 ✅ 完成，仅 Tar/Zstd | **1 周** | `Tar.aura` + `Zstd.aura` |
| **P4** | 三模式集成验证 | 2 周 | ✅ **100% 完成** | **2 周** | 端到端三模式对比 |
| **P5** | 性能基准与自举联动 | 3 周 | ✅ **100% 完成** | **3 周** | 性能基准 + 自举产物三模式 |
| **总计** | — | **17 周** | — | **10.5 周** | — |

**关键原则**：

1. **每个阶段可独立验收**——每阶段有明确的「完成判定」标准，不依赖后续阶段
2. **每个阶段可独立回退**——每阶段失败只需放弃本阶段，不影响已交付的阶段
3. **前置阶段是后置阶段的前提**——P1 依赖 P0，P2 依赖 P0，P3 依赖 P0，P4 依赖 P1+P2+P3，P5 依赖 P4
4. **三种执行模式并行**——P1 做 AOT，P2 做 JIT，P3 做 Std，P4 做集成，P5 做性能
5. **保留边界不变**——bootstrap + Cranelift + syscall 运行库（Rust 重写）+ AOT native 内容均不修改

#### P2.4 P2.2：FFI 边界实现（1.5 周）

**目标**：实现 bootstrap 侧 3 个 FFI 函数。

**产出**：
- `compiler/src/bootstrap/jit_ffi.rs`（3 个 FFI 函数实现）
- `compiler/tests/jit_ffi_tests.rs`（20+ 测试用例）

**FFI 函数定义**：

```text
@native fun jit_compile(clif_text: String): String
  输入：Cranelift 文本 IR（.clif）
  输出：base64 编码的机器码 blob（失败返回空串）

@native fun jit_load(blob_b64: String): String
  输入：base64 编码的机器码 blob
  输出：entry_token（失败返回空串）
  实现：mmap(RW) → copy → mprotect(RX) → 注册分发表

@native fun jit_call(entry_token: String, args: String, out_slot: Int): String
  输入：entry_token + args（记录表）+ out_slot
  输出：返回值（tag|payload）或 "DEOPT" 或空串
  实现：dispatch_table + call_indirect
```

#### P2.5 P2.3：派发接线（1.5 周）

**目标**：将纯 Aura 侧 JIT 模块与 VM 派发路径接线。

**派发逻辑**：
```text
VM 调用函数 → VmJitBridge.checkCall()
  → 已编译？ → "native"（走原生码）
  → 已跳过？ → "skip"（回退解释器）
  → 达阈值/Fix A 强制？ → tryJitCompile()
    → 白名单检查 → 预解码 → 优化 → Clif IR → FFI compile → FFI load → insert
  → 未达阈值 → "defer"
```

```text
P0（基础契约）
  │
  ├──→ P1（AOT 收尾）──→ P4（三模式集成）
  │                              │
  ├──→ P2（JIT 模式）──────────→ P4
  │                              │
  ├──→ P3（Std + 调试器）─────→ P4
  │                              │
  └────────────────────────────→ P5（性能基准）
```

**关键依赖**：
