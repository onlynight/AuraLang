# Aura 并发/多线程 — 实施路线图

## 总览

```
Phase A (2-3 周):  C 运行时原语 + AOT 函数声明
  │
  ├── A1: pthread/Win32 线程封装（aura_syscalls.c）
  ├── A2: Mutex/RwLock 封装
  ├── A3: 原子操作封装（__atomic_* / Interlocked*）
  ├── A4: Condvar/Barrier 封装
  ├── A5: 运行时函数表更新（codegen/aot/runtime.rs）
  └── A6: 测试（thread_pool_tests 扩展 + 新增）
  │
Phase B (4-6 周):  VM 运行时改造
  │
  ├── B1: Heap 加 Mutex 保护
  ├── B2: 新指令集定义 + 解码
  ├── B3: 解释器实现（thread_spawn/mutex/atomic）
  ├── B4: 协程跨线程调度（M:N 模型）
  ├── B5: Channel 事件驱动改造
  ├── B6: Actor 调度循环
  └── B7: 并发集成测试
  │
Phase C (2-3 周):  AOT 代码生成
  │
  ├── C1: emit.rs 并发指令 → LLVM IR
  ├── C2: 原子操作使用 LLVM 内建（@llvm.atomicrmw.*）
  ├── C3: 运行时函数表 + C 实现
  └── C4: AOT 并发测试
  │
Phase D (2-3 周):  JIT 后端
  │
  ├── D1: 并发指令编译
  ├── D2: 外部函数调用支持
  ├── D3: 多线程 JIT 编译去重
  └── D4: JIT 并发测试
  │
Phase E (2 周):  标准库 Aura 实现
  │
  ├── E1: Thread/Mutex/Atomic 类
  ├── E2: Future/Promise 抽象
  ├── E3: 改造 Coroutine.aura / Actor.aura
  └── E4: 文档 + 示例
```

**总预估**：12-17 周（不含自举编译器额外 10-12 周，见 08-自举编译器并发支持.md）

## 优先级排序

按 ROI（投入产出比）排序：

1. **P0 — C 线程 + Mutex + Atomic**（Phase A）：基础设施，后续一切依赖
2. **P1 — VM 多线程 + Actor 调度循环**（Phase B）：真正的并发执行
3. **P2 — AOT 代码生成**（Phase C）：性能关键路径
4. **P3 — 标准库 Aura 暴露**（Phase E）：用户 API
5. **P4 — JIT 并发**（Phase D）：最后优化

## 关键风险

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| Heap 全局锁性能瓶颈 | 中 | 先用全局锁保证正确，后续按需分片 |
| Windows/POSIX API 差异 | 中 | 在 aura_syscalls.c 中抽象跨平台层 |
| JIT 并发编译竞态 | 低 | Mutex 保护编译缓存 + 条件变量等待 |
| Actor 调度循环死锁 | 中 | 超时机制 + 看门狗线程 |
| 协程跨线程数据竞争 | 高 | 严格限制闭包捕获 + Send trait 检查 |

## 验证标准

每个 Phase 完成后必须：

1. ✅ 单元测试全部通过（`cargo test`）
2. ✅ 集成测试全部通过（`cargo test --features llvm`）
3. ✅ 无内存泄漏（Rust 编译器保证）
4. ✅ 无数据竞争（Rust 编译器保证 + 并发测试）
5. ✅ 跨平台可编译（POSIX + Windows）
