# Aura 并发/多线程 — 概览与差距分析

## 1. 现状全景

Aura 的并发设施当前分布在 4 层，每一层都存在不同程度的缺失：

```
┌─────────────────────────────────────────────────────────────────────┐
│  Layer 1: 标准库（Aura 源码）         aura/core/aura/lang/coroutine/ │
│  └─ Coroutine.aura + Actor.aura                                     │
│  └─ 纯模拟，全局 Map/List，无任何实际并发能力                          │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 2: VM 运行时（Rust）            compiler/src/vm/              │
│  └─ coroutine.rs / actor.rs / channel.rs / thread_pool.rs            │
│  └─ 协程单线程调度器 + Actor 消息队列 + Channel + ThreadPool           │
│  └─ ThreadPool 已实现但未暴露给 Aura                                  │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 3: AOT / C FFI                 compiler/src/std/cffi/         │
│  └─ aura_concurrent_* 函数全部是单线程空桩                             │
├─────────────────────────────────────────────────────────────────────┤
│  Layer 4: JIT                          compiler/src/vm/jit.rs        │
│  └─ 仅编译叶子整数函数，完全不处理并发指令                              │
└─────────────────────────────────────────────────────────────────────┘
```

## 2. 逐层差距

### 2.1 标准库层

| 能力 | Rust 对标 | Aura 现状 | 差距 |
|------|-----------|-----------|------|
| 协程 spawn | `std::thread::spawn` | `Coroutine.spawn(body)` 返回递增 ID | body 不在调用时执行，ask 时才惰性执行 |
| 协程 await | 无直接对标（Future） | `Coroutine.ask(co_id)` 阻塞等待 | 无挂起/恢复，无 `Future<T>` |
| Actor 消息 | 无直接对标（Erlang 风格） | `Actor.send(actor, msg)` | 仅存入 List，无人消费，无调度 |
| Actor ask | 无直接对标 | `Actor.reply(actor, msg)` | 永远返回 null |
| Actor 监督 | 无直接对标 | `Actor.supervise(parent, child)` | 空操作 |
| 跨进程 Actor | 无直接对标 | `Actor.spawnActorProcess` | 仅委托到单进程版 |

### 2.2 VM 运行时层

#### 协程调度器（`coroutine.rs`）
- ✅ 协程状态机（Ready/Suspended/Done）
- ✅ Yield / ResumeCoroutine 帧栈快照
- ❌ 纯单线程：`next_ready()` 轮转调度，无 OS 线程映射
- ❌ 无协程优先级、无抢占
- ❌ 无 `park/unpark` 语义

#### Actor 运行时（`actor.rs`）
- ✅ Actor 实例化、邮箱 FIFO、监督树、死亡策略
- ❌ `ask` 是伪阻塞：轮询 `response_queue`，空时返回 Null
- ❌ 注释："真正的阻塞需要协程调度器支持"
- ❌ 消息不会自动分发到 Actor 处理函数——没有调度循环
- ❌ 无消息处理回调机制

#### Channel（`channel.rs`）
- ✅ 有界/无界通道、send/recv/tryRecv
- ❌ send 非阻塞：缓冲区满时返回 false
- ❌ recv 非阻塞：空时立即返回 Null
- ❌ recv_timeout 使用 `thread::sleep` 轮询
- ❌ 无条件变量/事件通知机制
- ❌ 无 `channelClose`、`channelCapacity`、`channelTrySend`

#### ThreadPool（`thread_pool.rs`）
- ✅ `std::thread::spawn` OS 线程
- ✅ CPU 核心数自动配置
- ❌ 完全没有暴露给 Aura
- ❌ 任务只能是 `Box<dyn FnOnce() + Send>`，无法运行 Aura 函数

#### 缺失的同步原语

| 原语 | Rust | Aura VM | 状态 |
|------|------|---------|------|
| Mutex | `std::sync::Mutex` | ❌ | 未实现 |
| RwLock | `std::sync::RwLock` | ❌ | 未实现 |
| Atomic | `std::sync::atomic` | ❌ | 未实现 |
| Condvar | `std::sync::Condvar` | ❌ | 未实现 |
| Once | `std::sync::Once` | ❌ | 未实现 |
| Barrier | `std::sync::Barrier` | ❌ | 未实现 |
| mpsc | `std::sync::mpsc` | ❌ | 未实现 |
| park/unpark | `std::thread::park` | ❌ | 未实现 |
| JoinHandle | `std::thread::JoinHandle` | ❌ | 未实现 |

### 2.3 AOT / C FFI 层

`aura_std_cffi.c` 中并发函数全部是单线程空桩：

```c
// spawn — 仅返回递增 ID
int32_t aura_concurrent_spawn(const void *value) {
    return (int32_t)(++aura_concurrent_next_id);
}
// send — 完全空操作
void aura_concurrent_send(int32_t actor, const void *msg) { (void)actor; (void)msg; }
// ask — 永远返回 null
const void *aura_concurrent_ask(int32_t actor, const void *msg) { return 0; }
// coroutine_yield — no-op
void aura_coroutine_yield(const void *ctx) { (void)ctx; }
```

### 2.4 JIT 层

- JIT 仅编译叶子整数函数
- ❌ 不处理 `Yield`/`NewCoroutine`/`ResumeCoroutine` 指令
- ❌ 无并发相关指令的 JIT 后端

## 3. 与 Rust 标准库完整差距

### 3.1 std::thread

| Rust API | 说明 | Aura 状态 |
|----------|------|-----------|
| `thread::spawn(f)` | 创建 OS 线程 | ❌ |
| `thread::join()` | 等待线程结束 | ❌ |
| `thread::park()` | 线程停车 | ❌ |
| `thread::unpark()` | 唤醒线程 | ❌ |
| `thread::sleep()` | 休眠 | ⚠️ 仅内部使用 |
| `thread::scope()` | 作用域线程 | ❌ |
| `JoinHandle<T>` | 线程句柄 | ❌ |

### 3.2 std::sync

| Rust API | 说明 | Aura 状态 |
|----------|------|-----------|
| `Arc<T>` | 原子引用计数 | ✅ VM 层已有（不暴露给 Aura） |
| `Mutex<T>` | 互斥锁 | ❌ |
| `RwLock<T>` | 读写锁 | ❌ |
| `Condvar` | 条件变量 | ❌ |
| `Once<T>` | 一次性初始化 | ❌ |
| `OnceCell<T>` | 懒初始化 | ❌ |
| `Barrier` | 屏障 | ❌ |
| `atomic::AtomicU64` | 原子变量 | ❌ |
| `atomic::AtomicBool` | 原子布尔 | ❌ |
| `mpsc::channel()` | 多生产者单消费者通道 | ❌ |

### 3.3 std::future（异步生态）

| Rust API | 说明 | Aura 状态 |
|----------|------|-----------|
| `Future` trait | 异步计算抽象 | ❌ |
| `Promise`/`SharedFuture` | 共享异步结果 | ❌ |
| `async fn` | 异步函数 | ⚠️ 语法已支持但无真正调度 |
