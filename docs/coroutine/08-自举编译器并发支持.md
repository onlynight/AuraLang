# Aura 自举编译器 — 并发支持

> 本文分析完全 Aura 化（自举编译器）场景下的并发需求。
> 自举意味着：用 Aura 编写的 Aura 编译器，编译 Aura 编写的 Aura 编译器。
> 编译器自身使用并发 → 并发设施必须对编译器可见且可用。

## 2. 自举编译器的并发需求

### 2.1 编译器自身的并发使用

自举编译器编译自身时，需要并发来：

| 场景 | 并发需求 | 优先级 |
|------|---------|--------|
| 编译管线并行化 | 词法→语法→语义→HIR→MIR→发射 可部分并行 | P1 |
| 多线程编译缓存 | 避免重复编译 | P1 |
| 编译文件并行 | 多个 .aura 文件并行编译 | P2 |
| 增量编译 | 变更文件并行重编译 | P3 |
| 代码生成并行 | 函数级并行 LLVM IR 生成 | P2 |
| 优化 pass 并行 | 多 pass 并行运行 | P3 |

### 2.2 当前阻塞并行化的障碍

来自 `docs/compiler/编译器性能分析与优化建议.md` 的分析：

```rust
// compiler/src/codegen/hir.rs:58-75
// ★ 9 个 thread-local RefCell 全局
thread_local! {
    static HIR_DESUGAR_1: RefCell<X> = ...
    static HIR_DESUGAR_2: RefCell<X> = ...
    // ... 共 9 个
}
```

**结构性阻塞**：两个 desugarer 在同一进程内会竞争同一个 RefCell，无法并行。
**解决方案**：提取为显式的 `DesugarContext` 结构体，每个线程独立持有。

### 2.3 自举编译器的并发能力要求

```
自举编译器的并发能力分 3 级：

Level 1（必须）：编译器能使用并发 API
  - 能调用 Thread.spawn / Mutex.lock / Atomic.add
  - 能创建 Actor / Channel
  - 编译自身时不依赖 Rust 并发

Level 2（推荐）：编译器能并行化编译管线
  - 词法/语法分析可并行（per-file）
  - HIR 降糖可并行（per-function）
  - 代码生成可并行（per-function）

Level 3（可选）：编译器自身使用并发数据并行
  - 并行迭代器（par_iter）
  - 任务图调度
  - 工作窃取调度器
```

## 3. 自举编译器并发实现方案

### 3.1 Phase A: C 层并发原语（已存在 + 补充）

`aura_syscalls.c` 已有部分实现（Phase D.2 P3），需要补充：

| 已有 | 缺失 |
|------|------|
| `aura_thread_create/join` | `aura_thread_sleep/park/unpark/id` |
| `aura_mutex_new/lock/unlock/destroy` | `aura_mutex_trylock` |
| `aura_condvar_new/wait/signal/broadcast/destroy` | `aura_condvar_wait_timeout` |
| `aura_cpu_atomic_add`（x86_64 内联汇编） | 跨平台原子操作 |
| - | RwLock（读写锁） |
| - | Barrier（屏障） |
| - | TLS（线程本地存储） |

### 3.2 Phase B: VM 运行时并发

#### 3.2.1 自举编译器的 Heap

```
问题：自举编译器的 HIR/MIR 数据结构在 VM Heap 中，
      多线程编译需要共享 Heap 访问。

方案：
  1. 每个编译线程拥有独立的 VM 实例
  2. 编译中间产物（HIR/MIR）通过 Channel 传递
  3. 最终 IR 由主线程汇总

数据流：
  主线程 spawn N 个编译线程
       │
       ▼
  Thread 1: parse(file_1) → send(hir_1, channel)
  Thread 2: parse(file_2) → send(hir_2, channel)
  Thread 3: parse(file_3) → send(hir_3, channel)
       │
       ▼
  主线程: recv(channel) → merge(all_hirs) → emit(ir)
```

#### 3.2.2 编译器内部共享状态

```
自举编译器需要共享的状态：

1. 模块注册表（ModuleRegistry）
   - 只读（初始化后冻结）
   - 使用 OnceLock 保证一次性初始化

2. 原生函数注册表（NativeRegistry）
   - 只读
   - 使用 OnceLock

3. JIT 编译缓存（JitState）
   - 读多写少
   - 使用 RwLock + Condvar 防止重复编译

4. 编译中间缓存（CompilationCache）
   - 按文件路径缓存编译结果
   - 使用 RwLock<HashMap>
```

### 3.3 Phase C: 自举编译器并发代码生成

#### 3.3.1 并行编译管线

```
传统串行管线：
  File → Lex → Parse → Sema → HIR → MIR → Emit

并行管线（自举编译器）：
  ┌── File_1 → Lex → Parse → Sema → HIR ─┐
  ├── File_2 → Lex → Parse → Sema → HIR ─┤→ Merge → MIR → Emit
  ├── File_3 → Lex → Parse → Sema → HIR ─┤
  └── File_N → Lex → Parse → Sema → HIR ─┘

  其中 Emit 阶段也可并行：
    MIR → ┌── Func_1 → Emit ─┐
           ├── Func_2 → Emit ─┤→ Link → Binary
           ├── Func_3 → Emit ─┤
           └── Func_N → Emit ─┘
```

#### 3.3.2 编译器并发 API 依赖

自举编译器代码（Aura 编写）需要使用：

```aura
// 编译器并行编译文件
import aura.lang.std.Thread
import aura.lang.std.Mutex
import aura.lang.std.Atomic
import aura.lang.std.Channel

fun compileProject(sources: List<String>): Module {
    // 创建结果通道
    val resultCh = Channel.newChannel(0)
    
    // 并行编译每个文件
    for src in sources {
        Thread.spawn {
            val module = compileFile(src)
            Channel.channelSend(resultCh, module)
        }
    }
    
    // 收集所有结果
    val modules = mutableListOf()
    for i in sources.indices {
        modules.add(Channel.channelRecv(resultCh))
    }
    
    // 合并模块
    mergeModules(modules)
}
```

### 3.4 Phase D: 自举编译器的 RefCell 重构

当前 HIR 降糖代码有 9 个 thread-local RefCell 全局，需要重构：

```
// 当前（阻塞并行化）：
thread_local! {
    static DESUGAR_CONTEXT_1: RefCell<X> = ...
    static DESUGAR_CONTEXT_2: RefCell<X> = ...
    // ... 9 个
}

// 重构后（支持并行化）：
struct DesugarContext {
    context_1: X,
    context_2: X,
    // ...
}

// 每个线程独立持有自己的 DesugarContext
// 降糖函数接收 DesugarContext 作为参数
```

**对自举编译器的影响**：
- Rust 编译器代码需要重构
- Aura 编译器代码（自举层）需要同步实现 DesugarContext

### 3.5 Phase E: 自举编译器标准库并发

#### 3.5.1 编译器专用并发 API

自举编译器需要的并发 API 比普通应用更多：

```aura
package aura.lang.compiler.concurrent

/// 编译任务
internal class CompileTask {
    val file: String
    val module: Module  // 编译结果
    
    fun run(): Unit {
        this.module = compileFile(this.file)
    }
}

/// 并行编译调度器
internal class ParallelCompiler {
    private val workerCount: Int
    private val taskQueue: Queue<CompileTask>
    private val resultQueue: Queue<Module>
    private val mutex: Mutex
    
    fun compileAll(files: List<String>): List<Module> {
        // 创建任务
        for file in files {
            taskQueue.add(CompileTask(file))
        }
        
        // 启动工作线程
        val threads = mutableListOf()
        for i in workerCount {
            threads.add(Thread.spawn {
                workerLoop()
            })
        }
        
        // 等待所有任务完成
        for t in threads {
            t.join()
        }
        
        // 收集结果
        resultQueue.toList()
    }
    
    private fun workerLoop(): Unit {
        while true {
            mutex.lock()
            val task = taskQueue.tryPop()
            mutex.unlock()
            if task == null {
                return
            }
            task.run()
            resultQueue.add(task.module)
        }
    }
}
```

#### 3.5.2 并发安全的数据结构

自举编译器需要线程安全的数据结构：

```aura
/// 线程安全的队列
internal class ThreadSafeQueue<T> {
    private val data: List<T>
    private val mutex: Mutex
    
    fun add(item: T): Unit {
        mutex.lock()
        data.add(item)
        mutex.unlock()
    }
    
    fun tryPop(): T? {
        mutex.lock()
        if data.isEmpty() {
            mutex.unlock()
            return null
        }
        val item = data.removeAt(0)
        mutex.unlock()
        return item
    }
}

/// 线程安全的计数器
internal class AtomicCounter {
    private val value: AtomicInteger
    
    constructor() {
        this.value = AtomicInteger(0)
    }
    
    fun incrementAndGet(): Int {
        return value.incrementAndGet()
    }
    
    fun get(): Int {
        return value.get()
    }
}
```

4. 并行化编译验证

## 7. 自举编译器并发关键约束

```
┌────────────────────────────────────────────────────────────────────┐
│  约束 1: 自举编译器不能使用 Rust 并发原语                              │
│         - 编译器代码（Aura 部分）只能用 Aura 并发 API                  │
│         - 只有 bootstrap 层（Rust）可以使用 Rust 并发                  │
│                                                                     │
│  约束 2: 编译结果必须一致                                              │
│         - 串行编译结果 == 并行编译结果                                  │
│         - 不同并发度（1/N/Inf 线程）结果一致                            │
│         - 不同线程调度顺序结果一致                                      │
│                                                                     │
│  约束 3: 编译缓存线程安全                                              │
│         - 多线程同时访问 JIT 缓存无竞态                                │
│         - 多线程同时触发编译不重复编译                                   │
│         - 编译结果缓存（CompilationCache）线程安全                      │
│                                                                     │
│  约束 4: 内存安全                                                      │
│         - HIR/MIR 数据结构在跨线程传递时必须 Sendable                   │
│         - 无悬挂引用、无数据竞争                                         │
│         - Rust 编译器保证 + Miri 检测                                  │
│                                                                     │
│  约束 5: 死锁预防                                                      │
│         - 编译管线中锁顺序一致（Heap > Channel > JIT Cache）           │
│         - 无递归锁获取                                                  │
│         - 超时降级（锁等待超时 → 回退串行编译）                           │
└────────────────────────────────────────────────────────────────────┘
```
