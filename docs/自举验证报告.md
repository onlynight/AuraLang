## 6. 内存泄漏验证

### 6.1 检测机制

内存泄漏通过以下方式间接检测：

1. **ARC 平衡**：每个 Retain 操作必须有对应的 Release
2. **作用域结束**：变量出作用域后引用计数归零
3. **finally 清理**：所有 finally 块在作用域结束时执行

### 6.2 测试覆盖

| 场景 | 测试文件 | 验证方式 |
|------|----------|----------|
| 对象分配-释放 | memory_test.aura | 分配计数 = 释放计数 |
| 临时对象 | memory_test.aura | 出作用域后验证 |
| 函数返回对象 | memory_test.aura | 验证返回值正确 |
| GC 触发 | gc_test.aura | 1000 次分配 |
| 字符串生命周期 | gc_test.aura | 字符串创建和释放 |

### 6.3 长期泄漏检测

```
压力测试：1000 次分配-回收循环（memory_test.aura §10）
长时间 GC：1000 次分配循环（gc_test.aura §14）
```

预期：内存使用量在循环结束后回到基线水平。

### 8.5 编译器兼容性说明

当前 Aura 编译器（`aura.exe`）为早期版本，以下特性**暂不支持**：

| 特性 | 说明 | 替代方案 |
|------|------|----------|
| 嵌套函数 | 不能在函数内部定义 fun | 将函数移至顶层 |
| 多参数 listOf | `listOf(1, 2, 3)` | 使用 `listOf(单个)` 或循环构建 |
| data struct | `data struct` 关键字 | 使用 `struct` |
| println() 无参 | 空括号调用 | 使用 `println("")` |
| is 类型检查 | `x is Type` | 不使用 |
| import | 模块导入 | 不使用 |
| Lambda | 匿名函数 | 不使用 |
| 泛型函数 | `fun <T>` | 不使用 |
| defer | 延迟清理 | 使用 try-finally |
| .filter/.map/.take | 列表高阶操作 | 使用循环 |
| 字面量方法调用 | `42.toString()` | 先赋值给变量 |
| catch 类型注解 | `catch (e: String)` | 使用 `catch (e)` |

测试文件已针对这些限制进行了适配。
