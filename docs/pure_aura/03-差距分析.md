### B 阶段补记（2026-09-13）：HIR→IR 覆盖缺口已闭合

B.1–B.5 此前只是「HIR 有节点」，但 **Aura 侧 AOT 发射器不消费**这些节点 → 编译产物静默错误。
本轮按 `tests/pure_aura/hir_b*.aura` 逐个补齐，5 个用例在**载体与自举产物下均 PASS**：

| 用例 | 缺口 | 修复 |
|------|------|------|
| `hir_b2_lambda_tests` | `HirLambda` 在 `Emit.aura` **无任何分支** → lambda 调用恒返回 0；`(a, b) -> …` 括号参数 lambda 在 Aura 解析器里**是死代码**（第一个 `LParen` 分支抢先） | 新增闭包发射：`define <ret> @__lambda_N(i8* %env, …)` + env `{ i8* fn }` 堆分配 + 调用点间接调用（`load fn` → `call fn(env, args)`）；无注解形参按 **body 用法**推断类型（字符串拼接/字符串方法 → `i8*`）；`parsePrimary` 的 `LParen` 分支先试 `tryParseParenLambda` |
| `hir_b3_interp_tests` | 字符串**以插值开头**（`"$x …"`）时词法器不产出前置 `StringLiteral`，`parsePrimary` 无分支 → 首段丢失 | `parsePrimary` 增加 `StringInterpStart` 分支（合成空首段后走统一重建链路）；`prsIsWordLiteral` 改用**查表**判定（Aura 字符串关系比较不可靠，`"$" >= "a"` 实测为 true） |
| `hir_b4_try_tests` | `HirTry` 无发射分支 | `Parser.parseTry` 固定产出 `[body, catch, finally]` 三段（缺失补空 `Block` 占位）；`Emit.emitTry` 按无异常语义发射：body → 跳过 catch → 无条件 finally |
| `hir_b5_sigs_tests` | `toInt` / `toFloat` 未解析 → 静默返回 0（`Math.sqrt(16.0)` 强转恒为 0） | `emitCall` 增加 `toInt`/`toFloat` 内建（浮点走 `fptosi`/`sitofp`，字符串走新增 C 助手 `aura_str_to_int` / `aura_str_to_float`） |

> **另修**：Rust 侧 `desugar_cfor` 把 C 风格 for 的**步进赋值**降级为 `HirStmt::Expr(desugar_expr(inc))`，
> 而 `desugar_expr(Expr::Assign)` 只求值不回写 → 循环变量永不变 → **编译产物死循环**
>（实测 CPU 0%、内存不增长、进程卡死）。改为走 `desugar_expr_stmt`（`HirStmt::Assign`）。
> Aura 侧同类问题（`lowerLambda` 误用 `hirKidsAdd` 传字符串 → 自举产物里形参 id 变成垃圾）也一并修正。
> 新增 `tests/pure_aura/cfor_aot_tests.aura` 锁定该缺陷。

### C.2 完成记录（2026-09-13）

#### Rust 侧 `compiler/src/codegen/aot/emit.rs`（三缺口 + 连带缺陷）

| # | 问题 | 修复 |
|---|------|------|
| 1 | `@native(asm=…)` 通用指令无 inline asm（回退 no-op） | 生成真正的 `call <ret> asm sideeffect "…", "<constraints>"(<args>)`：补参数表 `()`、输出约束数与返回值个数对齐（`=r`）、形参按 `r` 传入；x86 目标前缀 `.intel_syntax noprefix`（仓库自带 FFI 片段即 Intel 写法） |

| 3 | void 返回拼接 `ret void` 格式问题 | 统一 `entry:` + `ret void`；未知 builtin 直接 `ret <默认值>`（不再产出 `%result = 0` 非法 IR） |
| 4 | （实测发现）call 实参缺 LLVM 类型 | syscall/alloc/free/atomic 全部补 `i64`——llc 否则报 `expected type` |
| 5 | （实测发现）`Long`/地址算术被截断 | 整型统一从「取较窄」改为「取较宽」（与 Aura 侧 `commonNumTy` 一致）：旧行为把 `Memory.alloc` 返回的堆地址 `+1` 后 `trunc i32`，高 32 位丢失直接访问违例 |
| 6 | （实测发现）`String.length` 被误判为列表计数 | 旧实现用「变量名以 s/str/msg 开头」的启发式判字符串，`p.length`（`p: String`）落到 `Collections.count(i8*)` 返回指针垃圾值。新增 **Aura 类型跟踪**（`EmitCtx::var_aura_types` / `func_ret_aura_types`，在形参、`val/var`、`for` 变量、函数返回类型处登记），按 Aura 类型区分 `String` 与 `List`；无类型信息时保留旧启发式 |

#### 本轮定位并修复的缺口（全部在 Aura 侧源码）

定位手段：**由 Aura 前端给自身源码做「解析体检」**（逐模块 `Parser.parseProgram()` 统计诊断）→ 把诊断行还原到源码 → 修前端；再用单文件探针在自举产物上复现崩溃点。列表按发现顺序：

| # | 文件 | 问题 | 修复 |
|---|------|------|------|
| 1 | `hir/Hir.aura` | `when` 保留 `HirWhen` 结构，而 Aura 侧发射器**只认 `HirIfExpr`** → 整个 when 表达式静默求值为 0（自举时 when 语义全错） | `lowerWhen` 改为与 Rust `desugar_when` 同构：从后往前构造嵌套 `HirIfExpr`，`else ->` 条件恒真 |
| 2 | `parser/Parser.aura` | `else ->` 分支模式走 `parseExpr`，`else` 是关键字 token → 诊断 + 反同步 | 模式位置识别 `Else`，降级为 `Ident("__else__")`（与 Rust 一致） |
| 3 | `parser/Parser.aura` | **C 风格 for**（`for (var j: Int = 0; j < i; j = j + 1)`）不支持：`parseFor` 直接 `prsExpect("In")` → 类体断链、其后的方法全部退化为顶层自由函数（丢失隐式 self） | `parseFor` 增加 C 风格分支（`Semicolon` 判定 + `parseStatement` 解析步进）；`Hir.lowerCFor` 降级为 `{ init; while (cond) { body; incr } }` |
| 4 | `parser/Parser.aura` | 无花括号的分支若是赋值（`if (c) x = y`）→ `parseExpr` 不消费 `=` → 诊断 + if/else 链反同步（Fold.aura 55 条诊断） | `parseBranch` 改走 `parseStatement`；HIR 新增 `lowerBranch`（语句分支包一层 `HirBlock`） |
| 5 | `parser/Parser.aura` | `;` 语句分隔符未跳过（Rust 允许单行多语句） | `parseBlock` / `parseProgram` 跳过 `Semicolon`；顺带修好 3 处把 token 种类写成 `"Semi"`（词法器实际产出 `"Semicolon"`）的失效判断 |
| 6 | `parser/Parser.aura` | 可见性修饰符 `private`/`protected`/`public` 落到表达式分支 → 「意外的 token: Private」 | `parseStatement` 跳过可见性修饰符 |
| 7 | `parser/Parser.aura` | `throw expr` 未支持（vm/*.aura 大量使用） | 表达式位置解析为 `Throw`；HIR 降级为 `HirCall("__throw", [e])`（与 Rust 同形） |
| 8 | `parser/Parser.aura` | 关键字作变量名/表达式（`val val: Int = …` 后的 `toStr(-val)`）被判为错误 → 整段反同步 | 声明名位置新增 `prsExpectDeclName`（接受硬关键字）；原子表达式位置把词字面量一律当标识符（对齐 Rust `advance().literal`） |
| 9 | `hir/Hir.aura` | 类方法扫描：`leafLit` 等**位于类体后半段**的方法未被识别为 owner → 发射为无 self 的裸符号（调用点/定义签名不一致 → 非法 IR/链接错误） | 随 #3 修复后自动恢复；新增用例锁死（`define i32 @Parser_leafLit(%struct.Parser*`） |

> 说明：#1–#9 都已计入 `tests/pure_aura/bootstrap_c4_tests.aura` 的不变量断言。B 阶段「HIR→IR」缺口已按 §二「B 阶段补记」全部闭合（`hir_b1`–`hir_b5` 在载体与自举产物下均 PASS）。仍在的**已知限制**：
> * 自举产物对**非法输入**（如 UTF-8 BOM、无法解析的 token）会在诊断路径上崩溃（载体则仅告警并继续）——不影响合法输入，属健壮性待补；
> * 自举产物在编译「导入 `Aot.aura`/`Linker.aura` 等模块的程序」时会崩溃（`probe_dump.aura` 复现）——与上一项同源（诊断/异常路径），不影响自举链路本身；
> * lambda 实现为**无捕获**闭包（自由变量按未定义变量处理），且不支持嵌套 lambda（子上下文状态只保存一层）。

## 七、v3.0 方向性修正（2026-09-14）

### 7.1 @native 误用诊断

v2.0 方案存在方向性错误：`@native` 被当作「C 函数桩」使用，导致所有工具链 .aura 文件变成无效空壳。

**诊断结果**：

| 文件 | 行数 | @native 声明数 | 问题 |
|------|------|---------------|------|
| Loom.aura | 672 | 6 个裸 @native | 函数名不在匹配表，生成空壳 |
| AuraCli.aura | 509 | 20 个裸 @native | 参数类型为 Int，丢失参数信息 |
| AuraLsp.aura | 316 | 11 个裸 @native | JSON-RPC 用字符串搜索模拟 |
| AuraDebugger.aura | 386 | 13 个裸 @native | 无 VM 交互 |

**根因**：裸 `@native`（无括号）被解析为 `NativeAttr::Builtin`，但 emit.rs 的函数名匹配表只覆盖 `alloc`/`free`/`read`/`write`，其余函数生成 `ret 0` 空壳。

### 7.2 v3.0 正确设计

`@native` 是**编译器 LLVM IR 生成指令**，三种注解形式全部由编译器直接生成纯 LLVM IR：

| 注解形式 | 编译器生成 | 运行时依赖 |
|---------|----------|-----------|
| `@native(N)` | 内联 `syscall` 指令 IR | 无 |
| `@native(asm="...")` | LLVM inline asm | 无 |
| `native fun` | 已知模式 IR（brk/mmap/load/store） | 无 |

详见 `docs/pure_aura/完全Aura化技术方案-v3.0.md`。

### 7.3 对阶段 D/E 的影响

| 阶段 | 原方案 | v3.0 修正 |
|------|--------|----------|
| D.3 | `aura_syscalls.c` 实现 syscall 分发 | 编译器 @native(N) 直接生成 syscall IR |
| D.3.3 | Memory builtin 走 C 函数 | native fun Memory.alloc → brk IR |
| E.1 | AuraCli.aura 用裸 @native | 改为调用 Aura 编译器函数或 native fun |
| E.2 | AuraLsp.aura 用裸 @native | 改为纯 Aura JSON 解析 + 编译器 API |
| E.3 | AuraDebugger.aura 用裸 @native | 改为编译器调试接口 |
| E.4 | Loom.aura 用裸 @native | 改为 @native(N) syscall 调用 |

## 八、风险与建议

### 风险

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| **R1** String 统一改动范围大，引入回归 | 中 | 高 | 保留 `string_as_struct=true` 作为 feature flag，分批切换 + 全量回归 |
| **R2** 双层并存导致 std 漂移 bug | 高 | 中 | 尽快落地「Aura 实现优先」机制，每改一个模块就删除对应 `std_*.rs` 注册 |
| **R3** 并发上移性能不达标 | 中 | 中 | 保留 C 实现 + FFI，仅调度逻辑上移 |
| ~~**R4** 自举验证长期未跑通~~ | — | — | 已跑通（§三），且 B 阶段 AOT 发射覆盖缺口已闭合（lambda / try-catch / 多段插值 / `toInt` 全 PASS）。新风险转为「自举产物在诊断/异常路径上不健壮」（非法输入、导入 `Aot.aura` 的程序），属健壮性待补 |

### 建议

1. **先做 A.2（String 统一）**——它是 D 阶段所有 String 操作正确性的前提，也是 C.2 自举编译器的基础。建议保留 `string_as_struct` feature flag 做渐进切换。

2. **紧接着做 D.1（优先级机制）**——解决「16 个 `.auc` 嵌入了但没被优先调用」的问题。每改一个模块的优先级，就删除对应的 `std_*.rs` `#[cfg(feature)]` 注册，减少漂移面。

3. **阶段 E 是可选的**——若接受「Rust CLI + Aura 编译器 + Aura std」模式，可跳过 E，在 ~7–11 周内完成脱 Rust（编译器 + VM + std 全部 Aura）。`aura` 命令本身仍为 Rust，但不再调用任何 Rust native std 函数。

4. **自举验证已跑通（2026-09-13）**——Stage-1/2/3 全链路成功，B 阶段 AOT 发射覆盖缺口（lambda / try-catch / 多段插值 / `toInt`）亦已闭合，`hir_b1`–`hir_b5` 在载体与自举产物下均 PASS（§二、§三）。下一步：把 `scripts/self-bootstrap.ps1` 与 `tests/pure_aura` 接进 CI，补自举产物的诊断路径健壮性；进入 E 阶段（CLI/LSP/loom 上移）的前提已具备。

5. **并发运行时（P3）是关键路径**——当前 Actor/Channel/Coroutine 嵌入后仍是单线程，`pthread` 封装是 Aura 侧调度器的前置条件，建议优先处理。
