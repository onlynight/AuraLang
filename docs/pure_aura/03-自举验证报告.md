## 二、自举流程（实测命令）

```powershell
# Stage-1：Rust 后端编译 Aura 编译器源码 → 原生载体
.\target\release\aura.exe build aura\compiler\aura\lang\compiler\Main.aura --aot --output build\bin\aura-compiler-c2.exe

# Stage-2：载体编译自身 → 自举产物
.\build\bin\aura-compiler-c2.exe aura\compiler\aura\lang\compiler\Main.aura -o build\bin\aura-compiler-native2.exe

# Stage-3：自举产物编译/运行用户程序（含 @native FFI）
.\build\bin\aura-compiler-native2.exe tests\pure_aura\native_c2_memory.aura -o build\test\mem.exe
.\build\test\mem.exe        # 期望 RESULT: PASS
```

Stage-2 规模：**51 个模块 / 57834 个 HIR 节点 / 链接后约 45 MB**，本机耗时约 **11 s**。

## 四、本轮修复的自举阻塞（9 类，全部在 Aura 侧源码）

定位方式：用 Aura 前端给**自身源码**做解析体检（逐模块统计诊断 → 还原到源码行），再用单文件探针在自举产物上复现崩溃点。

| # | 类别 | 关键修复 |
|---|------|----------|
| 1 | `when` 未降级 | `Hir.lowerWhen` 改为构造嵌套 `HirIfExpr`（此前保留 `HirWhen`，Aura 发射器不认 → when 恒为 0） |
| 2 | `else ->` 分支 | 模式位置识别 `Else` → `Ident("__else__")` |
| 3 | C 风格 `for` | `Parser.parseFor` 增加 C 风格分支；`Hir.lowerCFor` → `{ init; while (cond) { body; incr } }`（**修复前会让类体断链、后续方法丢失隐式 self**） |
| 4 | 无花括号分支为赋值 | `parseBranch` 改走 `parseStatement`；`Hir.lowerBranch` 把语句分支包进 `HirBlock` |
| 5 | `;` 语句分隔符 | `parseBlock`/`parseProgram` 跳过 `Semicolon`；修正 3 处把种类写成 `"Semi"` 的失效判断 |
| 6 | 可见性修饰符 | `private`/`protected`/`public` 在语句入口跳过 |
| 7 | `throw` 语句 | 解析为 `Throw` → `HirCall("__throw", [e])`（与 Rust 侧 HIR 同形） |
| 8 | 关键字作名字 | 声明名接受硬关键字；表达式位置词字面量一律按标识符（对齐 Rust `advance().literal`） |
| 9 | 类方法 owner 识别 | 随 #3 恢复：`Parser_leafLit(%struct.Parser* …)` 不再退化为裸 `@leafLit` |

### 四之二、B 阶段 AOT 发射覆盖（2026-09-13 追加）

| # | 类别 | 关键修复 |
|---|------|----------|
| 10 | lambda / 闭包 | `Emit.emitLambda`：`define <ret> @__lambda_N(i8* %env, …)` + env `{ i8* fn }` 堆分配 + 调用点间接调用；无注解形参按 body 用法推断 `i8*`/`i32`；`(a,b) -> …` 括号参数 lambda 接入 `parsePrimary`（此前是死代码） |
| 11 | 字符串插值首段 | `parsePrimary` 支持以 `StringInterpStart` 开头（合成空首段）；`prsIsWordLiteral` 改查表（Aura 字符串关系比较不可靠） |
| 12 | try/catch/finally | `Parser.parseTry` 固定三段 `[body, catch, finally]`；`Emit.emitTry` 顺序语义（body → 跳过 catch → 无条件 finally） |
| 13 | `toInt` / `toFloat` | 发射器内建（浮点 `fptosi`/`sitofp`，字符串走新增 C 助手 `aura_str_to_int` / `aura_str_to_float`） |
| 14 | C 风格 for 步进（**Rust 侧**） | `desugar_cfor` 步进赋值改走 `desugar_expr_stmt`（`HirStmt::Assign`）——原实现 `desugar_expr(Expr::Assign)` 只求值不回写，**编译产物死循环** |
| 15 | lambda 形参 id（**Aura 侧**） | `lowerLambda` 误用 `hirKidsAdd(hirKids, paramsStr)`（形参是 `Int`）→ 自举产物里 id 变垃圾、形参全丢；改用 `hirKidsConcat` |

详情与代码证据见 `03-差距分析.md` §三。

## 五、遗留缺口（不阻塞自举，但需后续补齐）

**已闭合（2026-09-13）**：B 阶段 AOT 发射覆盖缺口 —— lambda/闭包、try/catch/finally、多段（含首段即）字符串插值、`toInt(Math.sqrt(x))`。四项在**载体与自举产物下均 PASS**，见 §三 第 5/6 行与 §四之二。

仍在的限制：

| 缺口 | 现象 | 影响面 |
|------|------|--------|
| **非法输入健壮性** | 自举产物遇到 BOM/非法 token 会在诊断路径崩溃（载体仅告警继续） | 输入含 BOM 等非法字符时 |
| **自举产物编译「导入 Aot/Linker 模块的程序」崩溃** | `probe_dump.aura`（import `Aot.aura`/`ModuleLink.aura` 等）由自举产物编译时崩溃（载体正常） | 与上一项同源（诊断/异常路径），不影响自举链路本身 |
| **lambda 捕获** | 当前实现为无捕获闭包（自由变量按未定义变量处理）；不支持嵌套 lambda（子上下文状态只保存一层） | 使用捕获/嵌套 lambda 的程序 |
| **C 风格 for 的新增支持面** | 仅支持 `for (init; cond; incr)` 完整三段（`for (;;)` 这类省略形式未覆盖） | 省略 init/cond/incr 的写法 |

> 注：历史记录（上一版）里「载体一致 FAIL」的 lambda/try/插值/`toInt` 四项均属 **AOT 后端覆盖缺口**（Phase B「HIR→IR」），已按 §四之二 全部修复；这四项在修复前「载体与自举产物一致 FAIL」，修复后「一致 PASS」，两次一致本身就是自举正确性的证据。
