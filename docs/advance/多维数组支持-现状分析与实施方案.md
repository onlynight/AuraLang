### 1.4 核心问题链

```
用户代码: var m: Int[3][2] = [[1,2],[3,4],[5,6]]

Rust:  Int[3][2] → Type::Array(Array(Int))     ← 大小 3,2 丢失
       [[1,2],[3,4],[5,6]] → arrayListOf(...)  → Ty::List(List(Any))
       Ty::List(List(Any)).can_assign_to(Ty::Array(Array(Int))) = false  ← ❌ 编译报错

Aura:  Int[3][2] → "Int[3][2]" (字符串)         ← ✅ 大小保留
       [[1,2],[3,4],[5,6]] → __list_new(...)   → "Any" (TypeChecker不推断)
       m[0] → tcCheckIndex 返回 "Any"           ← ❌ 类型推断失败
       m[0][1] → 仍是 "Any"                     ← ❌ 无法提取元素类型
```

### 1.5 关键代码路径详解

#### Rust 编译器: 类型大小丢弃点

```rust
// seed/compiler/src/parser.rs:638-651
// 数组类型：Int[6] 或 Int[]
while self.check(TokenKind::LBracket) {
    self.advance(); // [
    if self.check(TokenKind::RBracket) {
        // 空数组类型 Int[]
        self.advance();
        ty = Type::Array(Box::new(ty));
    } else {
        // 有界数组类型 Int[6]：解析大小表达式后丢弃
        let _size_expr = self.parse_expression(0);  // ← 丢弃！
        self.expect(TokenKind::RBracket);
        ty = Type::Array(Box::new(ty));
    }
}
```

#### Rust 编译器: HIR 类型字符串化


#### Aura 编译器: 索引类型推断缺失

```aura
// aura/compiler/aura/lang/compiler/sema/TypeChecker.aura:866-878
fun tcCheckIndex(ast: Ast, id: Int): String {
    val kids: String = ast.kidsOf(id)
    val kCount: Int = kidsCount(kids)
    if (kCount >= 2) {
        val containerId: Int = kidsAt(kids, 0)
        val containerTy: String = this.tcCheckExpr(ast, containerId)
        this.tcCheckExpr(ast, kidsAt(kids, 1))

    return "Any"
}
```

#### Aura 编译器: 类型格式不统一

```
Parser 产出:     "Int[6]", "Int[3][2]"          ← 括号语法
TypeUtils 判断:  "Array<Int>", "List<Int>"      ← 尖括号语法
AOT TypeMapper:  "Array<...>" → i8*              ← 仅处理尖括号
canAssignTo:     字符串直接比较                  ← 无格式转换
```

```aura
// 现状: 仅 String→Char，其他全返回 "Any"
// 改为:
fun tcCheckIndex(ast: Ast, id: Int): String {
    val kids: String = ast.kidsOf(id)
    val kCount: Int = kidsCount(kids)
    if (kCount >= 2) {
        val containerId: Int = kidsAt(kids, 0)
        val containerTy: String = this.tcCheckExpr(ast, containerId)
        this.tcCheckExpr(ast, kidsAt(kids, 1))
        // 字符串索引 → Char
        if (TypeUtils.isString(containerTy)) {
            return "Char"
        }
        // List<T> 索引 → T
        if (containerTy.startsWith("List<") && containerTy.endsWith(">")) {
            val inner: String = containerTy.substring(5, containerTy.length() - 1)
            return inner
        }
        // Array<T> 索引 → T
        if (containerTy.startsWith("Array<") && containerTy.endsWith(">")) {
            val inner: String = containerTy.substring(6, containerTy.length() - 1)
            return inner
        }
        // Int[N] 索引 → Int（括号语法）
        if (containerTy.endsWith("]") && containerTy.contains("[")) {
            val lastBracket: Int = containerTy.lastIndexOf("[")
            return containerTy.substring(0, lastBracket)
        }
        // ArrayList<T> 索引 → T
        if (containerTy.startsWith("ArrayList<") && containerTy.endsWith(">")) {
            val inner: String = containerTy.substring(10, containerTy.length() - 1)
            return inner
        }
    }
    return "Any"
}
```

### P1：多维数组类型

#### P1.1 Rust 编译器

**P1.1.1 嵌套字面量类型推断** — `seed/compiler/src/sema/checker.rs`

当 `declared = Ty::Array(Ty::Array(Ty::Int))` 且 `init = Ty::List(Ty::List(Ty::Any))` 时，递归推断内层类型。在 `check_call` 的 `collection_factory_ty` 路径中，如果外层类型已知，递归推断内层类型：

```rust
// 当 callee 是 arrayListOf 且外层声明类型已知时，
// 用外层类型推断字面量元素类型
fn infer_array_literal_ty(declared: &Ty, literal_args: &[Expr]) -> Ty {
    match declared {
        Ty::Array { inner, .. } => {
            let elem_ty = infer_array_literal_ty(inner, literal_args);
            Ty::List(Box::new(elem_ty))  // 仍是 List 包装，但 elem 类型正确
        }
        _ => Ty::List(Box::new(Ty::Any)),
    }
}
```

**P1.1.2 嵌套下标类型检查验证**

当前 `checker.rs:2824-2854` 已支持：
- `Ty::Array(elem)` → 返回 `*elem`
- `Ty::Array(Ty::Array(Int))` → `m[0]` → `Ty::Array(Int)` → `m[0][1]` → `Int` ✅

需验证：当 `elem` 本身也是 `Ty::Array` 时，`can_assign_to` 是否通过。

#### P1.2 Aura 编译器

**P1.2.1 嵌套字面量类型推断**

Aura 编译器中，`[[1,2],[3,4]]` 解析为 `__list_new(__list_new(1,2), __list_new(3,4))`。
在 TypeChecker 中，当声明类型是 `"Int[3][2]"` 时，需要递归推断内层元素类型。

由于 Aura 编译器用字符串类型，`"Int[3][2]"` 的 `tcCheckIndex` 返回 `"Int[2]"`，再索引返回 `"Int"` — 已在 P0 中支持。

关键差距：`tcCheckExpr` 对 `__list_new` 调用返回 `"Any"`（因为 `__list_new` 不在函数表）。需在 `tcCheckExpr` 中为 `__list_new` 添加特殊处理，当上下文类型已知时推断元素类型。

**P1.2.2 TypeUtils: 增强 canAssignTo**


### P2：后端支持（AOT + VM）

#### P2.1 Rust AOT 多维数组

**文件**: `seed/compiler/src/codegen/aot/emit.rs`

已有 1D 定长数组支持（`alloca [6 x i32]` + `getelementptr`）。扩展到 2D/3D：

```rust
// Int[3][2] → alloca [3 x [2 x i32]]

// m[i][j] → getelementptr [2 x i32], ptr %row, i64 j
```

需在 `HirType::Array { inner, size }` 映射时递归处理内层类型：

```rust
fn llvm_array_type(hir_ty: &HirType) -> Option<String> {
    match hir_ty {
        HirType::Array { inner, size } if let Some(n) = size => {
            let elem = llvm_array_type(inner).unwrap_or_else(|| llvm_scalar_type(inner));
            Some(format!("[{} x {}]", n, elem))
        }
        _ => None,
    }
}
```

```aura
fun mapArrayBracketType(ty: String): String {
    // Int[3][2] → [3 x [2 x i32]]
    // 递归解析括号嵌套
    val lastBracket: Int = ty.lastIndexOf("[")
    if (lastBracket < 0) {
        return mapToLLVM(ty)  // 基本类型
    }
    val base: String = ty.substring(0, lastBracket)
    val dimStr: String = ty.substring(lastBracket + 1, ty.length() - 1)
    val dim: Int = toInt(dimStr)
    val elemTy: String = mapArrayBracketType(base)
    return "[" + dim + " x " + elemTy + "]"
}
```

```aura
package aura.lang.collection

/// 转置矩阵：[rows][cols] → [cols][rows]
fun transpose(m: Array<Array<Int>>): Array<Array<Int>> {
    val rows: Int = m.size
    val cols: Int = m[0].size
    var result = arrayListOf<Array<Int>>()
    var j: Int = 0
    while (j < cols) {
        var newCol = arrayListOf<Int>()
        var i: Int = 0
        while (i < rows) {
            newCol.add(m[i][j])
            i = i + 1
        }
        result.add(newCol)
        j = j + 1
    }
    return result
}

/// 展平二维数组
fun flatten(m: Array<Array<T>>): List<T> {
    var result = arrayListOf<T>()
    var i: Int = 0
    while (i < m.size) {
        var j: Int = 0
        while (j < m[i].size) {
            result.add(m[i][j])
            j = j + 1
        }
        i = i + 1
    }
    return result
}

/// 二维数组映射
fun map2D(m: Array<Array<T>>, f: (Int, Int, T) -> T): Array<Array<T>> {
    var result = arrayListOf<Array<T>>()
    var i: Int = 0
    while (i < m.size) {
        var newRow = arrayListOf<T>()
        var j: Int = 0
        while (j < m[i].size) {
            newRow.add(f(i, j, m[i][j]))
            j = j + 1
        }
        result.add(newRow)
        i = i + 1
    }
    return result
}

/// 矩阵乘法（Int 矩阵）
fun matrixMultiply(a: Array<Array<Int>>, b: Array<Array<Int>>): Array<Array<Int>> {
    val rowsA: Int = a.size
    val colsA: Int = a[0].size
    val colsB: Int = b[0].size
    var result = arrayListOf<Array<Int>>()
    var i: Int = 0
    while (i < rowsA) {
        var newRow = arrayListOf<Int>()
        var j: Int = 0
        while (j < colsB) {
            var sum: Int = 0
            var k: Int = 0
            while (k < colsA) {
                sum = sum + a[i][k] * b[k][j]
                k = k + 1
            }
            newRow.add(sum)
            j = j + 1
        }
        result.add(newRow)
        i = i + 1
    }
    return result
}

/// 二维数组回调遍历
fun forEach2D(m: Array<Array<T>>, f: (Int, Int, T) -> Unit): Unit {
    var i: Int = 0
    while (i < m.size) {
        var j: Int = 0
        while (j < m[i].size) {
            f(i, j, m[i][j])
            j = j + 1
        }
        i = i + 1
    }
}
```

## 四、风险与注意事项

### 4.1 Rust 编译器风险

1. **`Type::Array` 结构变更影响面大**：`Array(Box<Type>)` → `Array { inner, size }` 触发 **15-20 处 match 分支**更新。需逐一检查 `ty.rs`, `checker.rs`, `hir.rs`, `mono.rs`, `opt.rs`, `mir.rs`, `emit.rs`, `c_backend.rs`, `aot/emit.rs`。

2. **`HirType::Array` 新增变体**：当前 `Type::Array` 在 HIR 层被字符串化，新增 `HirType::Array` 后需更新所有 match 分支（`mono.rs`, `opt.rs`, `mir.rs`, `emit.rs`）。

3. **AOT 后端已有 1D 定长数组**：`phase6_5_aot_tests.aura:340-352` 证明 `alloca [6 x i32]` + `getelementptr` 路径已通。P2 只需递归扩展到 2D/3D。

4. **VM 后端可能已支持多维**：`GetIndex` 对 `Value::Ref(h)` 调用 `heap.get_index`，如果内层也是 `HeapData::Array`，嵌套索引自动工作。**需验证**，不需修改。

### 4.2 Aura 编译器风险

1. **TypeChecker 索引推断当前极度简化**：`tcCheckIndex` 仅处理 String→Char，对 Array/List 全返回 "Any"。P0 改动后，嵌套索引链（`arr[i][j]`）的类型推断依赖**每一步都返回正确的 elem 类型**，而非 "Any"。

2. **字符串类型格式不统一**：Parser 产出 `"Int[6]"`（括号语法），TypeUtils 判断用 `"Array<Int>"`（尖括号语法）。两种格式并存，需在 TypeUtils 中统一处理。

3. **Aura AOT TypeMapper 不处理括号语法**：`TypeMapper.aura:139` 只匹配 `Array<...>`，不匹配 `Int[6]`。需新增 `mapArrayBracketType` 方法。

4. **Aura VM newArray 布局与 vmListAt 可能不兼容**：`newArray` 产出的内存布局（`count@+0, count@+8, items@+16`）与 `AuraDynList` 的布局可能不同。需检查 `VmCollections.vmListAt` 是否兼容，若不兼容需新增 `vmArrayAt`。

5. **`__list_new` 返回类型未注册**：TypeChecker 中 `__list_new` 调用返回 `"Any"`，因为该函数不在函数签名表中。需添加特殊处理。

### 4.3 双编译器同步风险

1. **AST/HIR 结构差异**：Rust 编译器用 enum 树，Aura 编译器用扁平 arena。同一语法特性需在两套表示中各实现一次。

2. **类型表示差异**：Rust 用 `Ty` enum，Aura 用字符串。类型兼容规则（`can_assign_to`）需在各写一遍。

3. **测试需双跑**：每个测试文件需在 Rust 编译器和 Aura 编译器下各运行一次。

### 4.4 已有测试影响

- `tests/photon/P2/03_array_ops.aura` — 使用 `var arr: Int[5] = [1,2,3,4,5]` 模式，当前可能报错。P0 完成后应通过。
- `tests/phase6_5_aot_tests.aura:340-352` — 已有 1D 定长数组 AOT 测试覆盖，P2 扩展为 2D。
- `docs/collections/PLAN.md:218` — 明确标记 "Array 具体实现：暂不新增"，P3 需解除此限制。
