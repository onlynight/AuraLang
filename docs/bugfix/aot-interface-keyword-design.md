# AOT 直调接口设计：`extern interface` 关键字方案

## 设计动机

当前 `demo_aot_direct` 使用命令式调用：

```aura
// 问题：魔法数字、无类型安全、无函数名绑定
val module_id = load_shared_library("utils.dll")
val sum = call_func(module_id, 0, listOf(3, 4))
```

本方案提出 `extern interface` 关键字，将"声明式绑定外部函数签名"从 `extern` 中剥离，形成清晰的语法分层：

| 关键字 | 语义 | 运行时路径 |
|--------|------|-----------|
| `extern "C"` | 外部 C 函数声明 | C ABI 调用 |
| `extern interface` | 跨模块 AOT 接口绑定 | JitValue ABI 调用 |

---

## 语法设计

### 基本形式

```aura
// 声明接口，绑定到 utils.dll 的 AOT 导出
extern interface Utils = "utils.dll" {
    fun add(a: Int, b: Int): Int
    fun multiply(a: Int, b: Int): Int
    fun factorial(n: Int): Int
    fun power(base: Int, exp: Int): Int
}
```

### 调用方式

```aura
fun main() = {
    val sum = Utils.add(3, 4)
    val prod = Utils.multiply(3, 4)
    val fact = Utils.factorial(5)
    val pw = Utils.power(2, 10)
    println("add = " + toString(sum))
}
```

## 自动生成接口文件

编译 AOT 动态库时，自动生成 `.aura_interface` 文件，供外部调用方引用：

```bash
# 编译时自动生成接口文件
aura build libs/utils/src/lib.aura --aot --shared --output utils.dll
# → 生成 utils.dll + utils.aura_interface

# 或者显式指定 --export-interface
aura build libs/utils/src/lib.aura --aot --shared --output utils.dll --export-interface utils.aura_interface
```

生成的 `utils.aura_interface` 文件：

```aura
// Auto-generated by `aura build --export-interface`
// Source: libs/utils/src/lib.aura
extern interface Utils = "utils.dll" {
    fun add(a: Int, b: Int): Int
    fun multiply(a: Int, b: Int): Int
    fun factorial(n: Int): Int
    fun power(base: Int, exp: Int): Int
}
```

调用方通过 `include` 引用：

```aura
include "target/build/libs/utils/utils.aura_interface"

fun main() = {
    val sum = Utils.add(3, 4)
}
```

## 语法层设计

### AST 节点

```rust
pub struct ExternInterfaceDecl {
    pub name: String,              // 接口名，如 "Utils"
    pub lib_path: Option<String>,  // 库路径，None 时按模块名自动查找
    pub functions: Vec<FnDecl>,    // 函数声明列表
    pub span: Span,
}
```

### 解析规则

```
ExternInterfaceDecl := 'extern' 'interface' IDENT ['=' STRING] '{' FunctionDecl* '}'

FunctionDecl := 'fun' IDENT '(' ParamList? ')' ':' Type
ParamList    := Param (',' Param)*
Param        := IDENT (':' Type)?
```

### 与 extern 的区分

| 语法 | 解析器分支 | 语义 |
|------|-----------|------|
| `extern "C" { ... }` | `parse_extern_decl` | C ABI 外部函数 |
| `extern "rust" { ... }` | `parse_extern_decl` | Rust ABI 外部函数 |
| `extern interface Foo { ... }` | `parse_extern_interface_decl`（新增） | AOT 模块接口绑定 |

pub struct HirInterface {

pub enum FfiAbi {

## VM 层设计

### 调用链路

```
Aura 源码: Utils.add(3, 4)
    │
    ▼
AST: MemberAccess { object: Var("Utils"), name: "add", args: [3, 4] }
    │
    ▼
HIR: Call { callee: "Utils.add", args: [...] }
    │
    ▼
Bytecode: CallNative(idx)   // idx = natives 中 "Utils.add" 的索引
    │
    ▼
VM: do_call_native(idx)
    │
    ├─ natives[idx].ffi_abi == FfiAbi::Aura
    │
    ▼
call_aot_ffi(native, args)
    │
    ├─ 1. ensure_lib_loaded("utils")          // 加载 DLL
    ├─ 2. load_shared_library("utils.dll")     // AotRuntime 加载模块
    ├─ 3. func_name_map[module_id]["add"]      // 名称→索引映射
    ├─ 4. AotRuntime::call_func(module_id, func_idx, jit_args)
    └─ 5. 返回 JitValue → Value
```

## 与 `extern "C"` 的统一视角

| | `extern "C"` | `extern interface` |
|---|---|---|
| 关键字 | `extern` | `extern interface` |
| 语义 | 外部链接声明 | 模块接口绑定 |
| 编译参数 | `--aot --shared --cabi` | `--aot --shared` |
| 导出符号 | `aura_c_add` | `aura_aot_add!2!0!0!0` |
| 调用约定 | C ABI | JitValue ABI |
| 类型安全 | 手动映射 | 自动（JitValue 标签） |
| 函数命名 | 直接调用 `add(3, 4)` | 接口调用 `Utils.add(3, 4)` |
| 接口文件 | `export-header` → `.h` | `--export-interface` → `.aura_interface` |

## 可行性评估

### ✅ 可行

1. **语法层**：`extern interface` 在 `extern` 后紧跟 `interface`，解析器可在 `parse_extern_decl` 中判断
2. **AST/HIR 层**：新增结构体，与现有 `ExternDecl` 并列
3. **VM 层**：复用 `AotRuntime` 现有基础设施，只需增加名称→索引映射
4. **符号解析**：`parse_aot_symbol_name` 已能提取函数名
5. **接口生成**：复用 `export-header` 的 HIR→文本生成逻辑

### ⚠️ 风险

1. **接口名冲突**：多个 extern interface 声明同名函数时，需通过 `Utils.add` vs `Math.add` 区分
2. **库路径解析**：`lib_path` 为 `None` 时，按模块名自动查找的逻辑需定义
3. **include 解析**：`.aura_interface` 文件的 include 路径解析需支持相对路径

---

## 结论

**`extern interface` 关键字方案可行且推荐**：

1. **语义清晰**：`extern interface` = "外部模块接口声明"，与 `extern "C"` 的"外部链接声明"区分
2. **调用直观**：`Utils.add(3, 4)` 明确知道调用目标
3. **接口文件**：自动生成 `.aura_interface` 文件，调用方可直接 include
4. **扩展性好**：未来可支持接口继承、默认实现、多库绑定
5. **实现复杂度可控**：核心依赖组件均已存在
