## 基于 NovaOS 的下一代系统级脚本语言

# 第一章：项目概述

## 1.1 项目背景

NovaOS 是一套基于 Linux 底层构建的上层 Framework 框架系统，采用 Raylib 作为渲染框架，通过微服务架构（AMS、IMS、WMS 等）提供服务，上层使用 LuaJIT 作为脚本虚拟机，应用层采用 Lua 开发，通过 FFI 调用 Raylib 等系统组件。

当前方案存在性能瓶颈和开发体验不足的问题，需要一种新的脚本语言来替代 Lua，提供：
- **C 语言级别的执行效率**
- **Python 级别的开发体验**
- **现代化语言特性**
- **与 NovaOS 架构深度集成**

## 1.2 语言定位

**Aura** 是专为 NovaOS 设计的系统级脚本语言，定位为 "LuaJIT 的完美继任者"：

- **语法层**：Kotlin 风格，零学习成本
- **执行层**：AOT + JIT 混合编译，接近 C 性能
- **生态层**：声明式包管理，去中心化依赖
- **集成层**：零开销 FFI，无缝调用 C/Raylib

## 1.3 核心设计目标

| 目标 | 实现方式 | 对标 |
|------|---------|------|
| C级执行效率 | AOT编译 + 栈分配 + 无GC | C/Rust |
| Kotlin开发体验 | 完全兼容Kotlin语法 | Kotlin |
| Python包管理 | 声明式依赖 + 去中心化 | Python/Go |
| 零开销FFI | C ABI直接调用 | Rust/C |
| 系统集成 | 原生支持NovaOS微服务 | - |

# 第二章：语言设计

## 2.1 语言命名

**Aura**（光环）

寓意：执行时如"光环"般高效、纯净，直抵硬件；同时暗示其"照亮"NovaOS 生态的角色。

## 2.2 设计哲学

### 核心原则
> **"语法100% Kotlin，底层100%原生"**

1. **Kotlin兼容**：类型系统、语法特性完全对齐 Kotlin
2. **性能优先**：栈分配、零成本抽象、无 GC
3. **安全可控**：空安全、类型安全、内存安全（ARC）
4. **显式优于隐式**：内存分配、错误处理、类型转换显式声明
5. **系统脚本化**：既有脚本的开发效率，又有系统级的执行效率

### 设计权衡

| 维度 | 取舍 | 理由 |
|------|------|------|
| 语法 | 完全兼容Kotlin | 降低学习成本，复用生态 |
| 内存 | ARC + 栈分配 | 避免GC暂停，确定性回收 |
| 类型 | 静态 + 类型推断 | C级性能，同时保持简洁 |
| 错误 | Result + 异常 | 兼顾安全性和易用性 |
| 并发 | Actor + 协程 | 适配微服务架构 |

## 3.6 错误处理

### Result 类型（推荐）

```aura
// 返回Result
fun loadTexture(path: String): Result<Texture, Error> {
    val tex = raylib.LoadTexture(path.toCStr())
    return if (tex.isNull()) {
        Result.Error(Error("Failed to load: $path"))
    } else {
        Result.Success(tex)
    }
}

// 使用Result
val result = loadTexture("sprite.png")
when (result) {
    is Result.Success -> drawTexture(result.data)
    is Result.Error -> log(result.error.message)
}

// 链式调用（类似Rust的?操作符）
fun loadAndRender(path: String): Result<Unit, Error> {
    val tex = loadTexture(path)?  // 错误自动传播
    renderTexture(tex)
    return Result.Success(Unit)
}
```

### 异常处理（可选）

### Actor模型（NovaOS微服务）

```aura
// Actor定义
actor WindowManager {
    // 私有状态
    private var windows: List<Window> = emptyList()
    private var focused: Int = -1
    
    // 消息处理器
    fun onCreate(config: WindowConfig): Window {
        val win = Window(config)
        windows = windows + win
        return win
    }
    
    fun onFocus(id: Int) {
        if (id < windows.size) {
            focused = id
        }
    }
    
    fun onClose(id: Int) {
        windows = windows.filter { it.id != id }
    }
}
```

# 第五章：编译系统

## 5.1 编译模式

### 三种编译模式

```bash
# 1. 字节码模式（默认）→ 跨平台
aura build main.aura          # 生成 main.auc

# 2. AOT模式 → 极致性能
aura build main.aura --aot    # 生成原生可执行文件

# 3. JIT模式 → 开发调试
aura run main.aura            # 解释执行 + 热点编译
```

### 分层编译策略

| 场景 | 模式 | 性能 | 跨平台 | 使用场景 |
|------|------|------|--------|---------|
| 开发调试 | JIT | C的70% | ✅ | 快速迭代 |
| 应用发布 | 字节码 | C的40-50% | ✅ | 热更新脚本 |
| 系统服务 | AOT | C的95% | ❌ | AMS/IMS/WMS |
| 混合模式 | Hybrid | 核心AOT，脚本字节码 | 混合 | NovaOS应用 |

# 第九章：LLVM 后端深度设计

> 本章详细阐述 Aura 编译器与 LLVM 集成的完整技术方案，覆盖 IR 生成器、类型映射、控制流、FFI 处理、优化 Pipeline、目标代码生成、交叉编译与 Runtime 集成。

## 9.1 设计目标与选型

### 9.1.1 设计目标

将 LLVM 作为 Aura 编译器的 AOT 后端，实现：

- **跨平台编译**：Windows 开发机 → ARM Linux（树莓派）等目标平台
- **C 级性能**：利用 LLVM 的工业级优化 pipeline
- **开发体验**：Aura 开发者无需关心底层 LLVM 细节
- **可维护性**：通过 LLVM IR 作为中间层，解耦前端与后端

```rust
pub struct TypeMapper<'ctx> {
    context: &'ctx Context,
}

impl<'ctx> TypeMapper<'ctx> {
    pub fn map(&self, aura_type: &AuraType) -> BasicTypeEnum<'ctx> {
        match aura_type {
            AuraType::Int => self.context.i32_type().as_basic_type_enum(),
            AuraType::Long => self.context.i64_type().as_basic_type_enum(),
            AuraType::Short => self.context.i16_type().as_basic_type_enum(),
            AuraType::Byte => self.context.i8_type().as_basic_type_enum(),
            AuraType::Float => self.context.f32_type().as_basic_type_enum(),
            AuraType::Double => self.context.f64_type().as_basic_type_enum(),
            AuraType::Boolean => self.context.bool_type().as_basic_type_enum(),
            AuraType::Char => self.context.i16_type().as_basic_type_enum(),

            // 字符串 → C 字符串指针 (*mut i8)
            AuraType::String => {
                self.context.i8_type().ptr_type(AddressSpace::default())
                    .as_basic_type_enum()
            }

            // 结构体
            AuraType::Struct(fields) => {
                let llvm_fields: Vec<BasicTypeEnum> = fields
                    .iter().map(|f| self.map(&f.ty)).collect();
                self.context.struct_type(&llvm_fields, false).as_basic_type_enum()
            }

            // 枚举 → tagged union [tag: i32, union: ...]
            AuraType::Enum(variants) => self.map_enum(variants),

            // 指针
            AuraType::Pointer(inner) => {
                let inner_ty = self.map(inner);
                inner_ty.ptr_type(AddressSpace::default()).as_basic_type_enum()
            }

            // 泛型（单态化后具体类型）
            AuraType::Generic(name, args) => self.map_generic(name, args),

            // 函数类型 → 函数指针
            AuraType::Function(params, return_type) => {
                let param_types: Vec<BasicTypeEnum> = params.iter()
                    .map(|p| self.map(p)).collect();
                let return_ty = self.map(return_type);
                return_ty.fn_type(&param_types, false)
                    .ptr_type(AddressSpace::default()).as_basic_type_enum()
            }
        }
    }
}
```

### 9.2.3 函数生成

```rust
impl<'ctx, 'a> FunctionGenerator<'ctx, 'a> {
    pub fn generate(&mut self, func: &AuraFunction) -> Result<(), CodegenError> {
        let llvm_func = self.get_or_create_function(func)?;
        let entry_block = self.context.append_basic_block(llvm_func, "entry");
        self.builder.position_at_end(entry_block);
        self.handle_parameters(func, llvm_func)?;
        self.generate_body(&func.body)?;
        self.generate_return(&func.return_type, &func.body)?;
        Ok(())
    }

    fn generate_statement(&mut self, stmt: &AuraStatement) -> Result<Value, CodegenError> {
        match stmt {
            AuraStatement::VariableDeclaration(name, ty, expr) => {
                let llvm_ty = self.type_mapper.map(ty);
                let alloca = self.builder.build_alloca(llvm_ty, name);
                if let Some(expr) = expr {
                    let value = self.generate_expression(expr)?;
                    self.builder.build_store(alloca, value);
                }
                self.scope.declare(name, alloca);
                Ok(alloca.into())
            }
            AuraStatement::Assignment(target, value) => {
                let llvm_value = self.generate_expression(value)?;
                let target_ptr = self.scope.lookup(target)?;
                self.builder.build_store(target_ptr, llvm_value);
                Ok(llvm_value)
            }
            AuraStatement::If(cond, then_block, else_block) => {
                self.generate_if(cond, then_block, else_block)
            }
            AuraStatement::Loop(cond, body) => {
                self.generate_loop(cond, body)
            }
            AuraStatement::Return(expr) => {
                let llvm_value = self.generate_expression(expr)?;
                self.builder.build_return(Some(&llvm_value));
                Ok(llvm_value)
            }
        }
    }
}
```

### 9.2.4 控制流生成

```rust
fn generate_if(
    &mut self,
    condition: &AuraExpression,
    then_block: &AuraBlock,
    else_block: &Option<AuraBlock>,
) -> Result<Value, CodegenError> {
    let current_func = self.builder.get_insert_block().unwrap().get_parent().unwrap();
    let then_bb = self.context.append_basic_block(current_func, "then");
    let else_bb = self.context.append_basic_block(current_func, "else");
    let merge_bb = self.context.append_basic_block(current_func, "merge");

    let cond_value = self.generate_expression(condition)?;
    self.builder.build_conditional_branch(cond_value.into_int_value(), then_bb, else_bb);

    self.builder.position_at_end(then_bb);
    self.generate_block(then_block)?;
    self.builder.build_unconditional_branch(merge_bb);

    if let Some(else_block) = else_block {
        self.builder.position_at_end(else_bb);
        self.generate_block(else_block)?;
    } else {
        self.builder.position_at_end(else_bb);
        self.builder.build_unconditional_branch(merge_bb);
    }

    self.builder.position_at_end(merge_bb);
    Ok(self.builder.build_phi(...)?)
}

fn generate_loop(
    &mut self,
    condition: &AuraExpression,
    body: &AuraBlock,
) -> Result<Value, CodegenError> {
    let current_func = self.builder.get_insert_block().unwrap().get_parent().unwrap();
    let cond_bb = self.context.append_basic_block(current_func, "loop_cond");
    let body_bb = self.context.append_basic_block(current_func, "loop_body");
    let end_bb = self.context.append_basic_block(current_func, "loop_end");

    self.builder.build_unconditional_branch(cond_bb);

    self.builder.position_at_end(cond_bb);
    let cond_value = self.generate_expression(condition)?;
    self.builder.build_conditional_branch(cond_value.into_int_value(), body_bb, end_bb);

    self.builder.position_at_end(body_bb);
    self.generate_block(body)?;
    self.builder.build_unconditional_branch(cond_bb);

    self.builder.position_at_end(end_bb);
    Ok(self.context.i32_type().const_int(0, false).as_basic_value_enum())
}
```

## 9.3 FFI 处理

### 9.3.1 外部函数声明

```rust
impl<'ctx, 'a> FfiGenerator<'ctx, 'a> {
    pub fn generate_ffi_declarations(
        &mut self,
        ffi_decls: &[FfiDeclaration],
    ) -> Result<(), CodegenError> {
        for decl in ffi_decls {
            match decl {
                FfiDeclaration::Library { name, functions } => {
                    for func in functions {
                        self.generate_extern_function(name, func)?;
                    }
                }
                FfiDeclaration::Constant { name, ty, value } => {
                    self.generate_extern_constant(name, ty, value)?;
                }
            }
        }
        Ok(())
    }

    fn generate_extern_function(
        &mut self,
        lib_name: &str,
        func: &AuraFunction,
    ) -> Result<(), CodegenError> {
        let llvm_return_ty = self.type_mapper.map(&func.return_type);
        let llvm_param_tys: Vec<BasicTypeEnum> = func.parameters
            .iter().map(|p| self.type_mapper.map(&p.ty)).collect();

        let fn_type = llvm_return_ty.fn_type(&llvm_param_tys, false);
        let llvm_func = self.module.add_function(
            func.name.as_str(), fn_type, Some(Linkage::External),
        );
        llvm_func.set_call_conv(CallingConvention::C);
        llvm_func.set_alias_name(&format!("{}_{}", lib_name, func.name));
        Ok(())
    }
}
```

### 9.3.2 FFI 调用生成

```rust
fn generate_ffi_call(
    &mut self,
    func_name: &str,
    args: &[AuraExpression],
) -> Result<Value, CodegenError> {
    let llvm_func = self.module.get_function(func_name)
        .ok_or(CodegenError::UndefinedFunction(func_name.to_string()))?;

    let mut llvm_args = Vec::new();
    for arg in args {
        llvm_args.push(self.generate_expression(arg)?);
    }

    let call = self.builder.build_call(
        llvm_func, &llvm_args, format!("ffi_call_{}", func_name).as_str(),
    );
    call.set_calling_convention(CallingConvention::C);

    Ok(call.try_as_basic_value().left().unwrap_or(
        self.context.i32_type().const_int(0, false).as_basic_value_enum()
    ))
}
```

```rust
impl<'ctx, 'a> Optimizer<'ctx, 'a> {
    pub fn optimize(&mut self, level: OptimizationLevel) -> Result<(), CodegenError> {
        self.add_standard_passes(level)?;
        self.add_aura_specific_passes(level)?;
        self.pass_manager.run_on(&self.module)?;

        if let Err(e) = self.module.verify(true) {
            return Err(CodegenError::VerificationFailed(e));
        }
        Ok(())
    }

    fn add_standard_passes(&mut self, level: OptimizationLevel) -> Result<(), CodegenError> {
        match level {
            OptimizationLevel::None => {
                self.pass_manager.add_pass("verify");
            }
            OptimizationLevel::Balanced => {
                self.pass_manager.add_pass("early-cse");
                self.pass_manager.add_pass("simplify-cfg");
                self.pass_manager.add_pass("reassociate");
                self.pass_manager.add_pass("licm");
            }
            OptimizationLevel::Aggressive => {
                self.pass_manager.add_pass("function-attrs");
                self.pass_manager.add_pass("globals-aa");
                self.pass_manager.add_pass("gvn");
                self.pass_manager.add_pass("indvars");
                self.pass_manager.add_pass("loop-unroll");
                self.pass_manager.add_pass("inline");
                self.pass_manager.add_pass("constprop");
                self.pass_manager.add_pass("instcombine");
            }
            _ => { /* O3/Os/Oz 类似 */ }
        }
        Ok(())
    }

    fn add_aura_specific_passes(&mut self, _level: OptimizationLevel) -> Result<(), CodegenError> {
```

```rust
pub extern "C" fn aura_arc_increment(ptr: *mut c_void) {
    let counter = ptr as *mut AtomicI32;
    unsafe { (*counter).fetch_add(1, Ordering::SeqCst); }

#[no_mangle]
pub extern "C" fn aura_arc_decrement(ptr: *mut c_void) {
    let counter = ptr as *mut AtomicI32;
    unsafe {
        if (*counter).fetch_sub(1, Ordering::SeqCst) == 1 {
            drop(Box::from_raw(ptr));
        }
    }
}
```

链接时，代码生成器自动注入 runtime 库的函数声明：

```rust
fn link_runtime(&mut self, runtime_lib: &str) -> Result<(), CodegenError> {
    let runtime_functions = [
        ("aura_arc_increment", "void", &["*mut c_void"]),
        ("aura_arc_decrement", "void", &["*mut c_void"]),
        ("aura_coroutine_yield", "void", &["*mut c_void"]),
    ];

    for (name, ret, params) in runtime_functions {
        let llvm_ret_ty = self.type_mapper.map_type(ret);
        let llvm_param_tys: Vec<BasicTypeEnum> = params.iter()
            .map(|p| self.type_mapper.map_type(p)).collect();
        let fn_type = llvm_ret_ty.fn_type(&llvm_param_tys, false);
        self.module.add_function(name, fn_type, Some(Linkage::External));
    }

    self.module.set_debug_info(true);
    self.module.set_module_flag("runtime_lib", runtime_lib);
    Ok(())
}
```

# 第十章：LSP 与开发者工具链

> 本章阐述 Aura 语言服务器协议（LSP）的设计方案，包括与编译器共享核心架构、LSP 服务器实现、CLI 入口、编辑器集成以及高级特性与 AI 助手整合。

## 10.1 核心设计：与编译器共享核心，分层实现

LSP 服务器的核心任务是提供语言智能（代码补全、跳转定义、诊断等）。为避免重复造轮子，最佳实践是与编译器/解释器**共享核心的前端逻辑**。

### 10.1.1 共享核心库 (`aura-core`)

`aura-core` 是整个工具链的基石，用 **Rust** 实现：

- **词法/语法分析器**：将源码解析为抽象语法树（AST）
- **语义分析器**：处理符号解析、类型推断与检查
- **增量编译引擎**：LSP 服务器性能的关键。当用户编辑文档时，增量编译引擎能快速重新分析**变更部分**，并将结果高效地反馈给 LSP 服务器

### 10.1.2 LSP 服务器 (`aura-lsp`)

`aura-lsp` 是一个独立的守护进程，通过 JSON-RPC 协议与编辑器通信。它不包含文件 I/O 或用户界面，职责是：

- **依赖核心库**：调用 `aura-core` 完成所有繁重的代码分析工作，自身负责将请求和参数转发给核心库，并将结果包装成 LSP 协议格式返回
- **管理文档状态**：维护内存中所有打开文档的版本和 AST 缓存
- **提供 LSP 功能**：实现标准的 LSP 请求：
  - `textDocument/completion` — 代码补全
  - `textDocument/definition` — 跳转到定义
  - `textDocument/hover` — 悬停时的类型/文档信息
  - `textDocument/diagnostic` — 主动推送代码错误与警告
  - `textDocument/formatting` — 代码格式化支持

```
│     │  - 增量更新处理              │         │
│     └──────────┬──────────────────┘         │
```

## 10.5 高级特性与优化

### 10.5.1 增量更新 (`textDocument/didChange`)

当用户输入时，编辑器发送变更的文本范围（而非整个文件内容），LSP 服务器只需增量更新 AST，分析效率大幅提升。

### 10.5.2 与 AI 助手深度整合

LSP 提供的基础能力可以成为 AI 助手的"眼睛"和"手"：

- **获取上下文**：AI 可通过 LSP 查询当前光标处的类型、符号定义、文档结构等，生成更贴合当前代码的智能补全
- **执行代码操作**：AI 可通过 LSP 请求执行"代码修复"或"重命名符号"等操作，并将变更直接应用到编辑器中
- **验证生成的代码**：AI 生成代码后，可借助 LSP 的 `textDocument/diagnostic` 能力，获取编译器诊断信息并自我修正

## 10.6 实施路径

| 阶段 | 任务 | 说明 |
