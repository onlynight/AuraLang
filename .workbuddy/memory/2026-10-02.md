- 验收：`aura run tests/pure_aura/p3_debugger_tests.aura` → **79 pass / 0 fail**（`=== P3.5 PASSED ===`）。

**三个真实缺陷（按发现顺序）：**

1. **`aura.lang.debugger.*` 无包根映射**（`codegen/mod.rs`）
   - 症状：`unresolved reference 'DebugVm'` + `未解析的函数调用 'DebugVm'`。
   - 修复：新增 `DEBUGGER_PKG_ROOT = "aura.lang.debugger."` + `debugger_pkg_root`
     路径（`aura/toolchain/debugger/aura/lang/debugger/`），在 `LANG_PKG_ROOT`
     **之前**分派；`resolve_aura_imports_rec` 增加第 6 个参数并透传。

2. **`ArrayList<T>` 接收者的全部列表 API 失效**（`vm/heap.rs` 等）——**通用引擎缺陷**
   - 根因：`ListPush/ListLen/list_set/get_index/set_index` 只认 `HeapData::List` 槽；
     而 `ArrayList<T>()` 是 `HeapData::Object`（类实例），其**字段 0** 才是真列表 →
     `add` 静默无操作、`size` 恒 0、`get(i)` 返回 null、`isEmpty` 恒 true。
   - 修复：
     - `Heap::list_slot(handle)`：把「列表接收者句柄」解包为承载真实元素的槽句柄
       （直接 `List` 槽，或 `Object` 的字段 0）。
     - `list_push/pop/len/set`、`get_index/set_index` 全部改走 `list_slot`。
     - 新增 `Heap::list_contains` / `list_index_of`。
     - 新增三条**堆句柄感知**指令 `ListIsEmpty`(112) / `ListContains`(113) /
       `ListIndexOf`(114)，贯穿 opcode → vm/mod → interp → mir → emit → debugger。
     - `hir.rs` 把 `isEmpty`/`contains`/`indexOf` 从 `Collections.*`（只认内联
       `Value::List`）改派到上述内建。
     - `std_collections.rs` 的 `nat_is_empty` 不再对 `Value::Ref` 谎报 `true`。

3. **`ArrayList.remove(i)` 永远抛 "index: N, size: 0"**（本轮定位并修复）
   - 根因：`ArrayList._size` 是普通实例字段，但 `add` 走 `__list_push` **原地追加、
     从不回写 `_size`** → 运行期 `_size` 恒为 0；而 `remove` 的越界检查 `index >= _size`
     因此必抛。`getSize`/`size`/`count`/`isEmpty` 早已被 HIR 改派到 `__list_len` 等
     内建（见 `hir.rs` 注释），**唯独 `remove` 漏了**。
   - 修复：新增 `Heap::list_remove_at` + `ListRemoveAt`(115) 指令（全链路）+ `__list_remove_at`
     内建 + HIR 对列表接收者的 `remove(i)`/`removeAt(i)` 改派（仅 1 参下标形态；
     `remove(item)` 按值删除保留原路径）。
   - 实测：`["a","b","c","d"].remove(1)` → 返回 `"b"`，余 `"acd"`，size=3 ✅

**另发现 2 个既有 VM 限制（非 P3.5 引入，已在测试中规避并记录）：**
- **模块级 `val` 非整数会退化为 0**：`globals: Arc<Mutex<Vec<i64>>>`（与 AOT 的
  `global i64` 一致；`Value` 含 `Rc<str>` 非 `Send`）。测试内的字节码/函数表/常量池
  改用**函数返回**规避。
- **`DebugVm` 的 `DECL_LOCAL n` 不消费操作数栈**（只 `setLocal(n,"0")`），
  故测试字节码改用 `STORE_LOCAL` 才是"赋值"语义。

**第 3 项修复的延伸（`_size` 一族彻底收敛）：**
- 上一条只修了 `remove`。进一步排查发现 `ArrayList` 里**所有未被 HIR 改派、仍读
  `_size` 的方法**都失效：`first`/`last`/`lastIndexOf`/`skip`/`take`/`sum`/`min`/
  `max`/`distinct` 等（实测 `lastIndexOf` 恒 -1、`skip(1).size` 恒 0、`sum` 恒 0）。
- 采用**单点收敛修法**：`Heap::list_push` / `list_pop` / `list_remove_at` 在
  「接收者是类实例（`target != handle`）」时**同步写回 `_size` 字段**
  （新增私有 `Heap::sync_list_size_field`，用与 `emit::field_index` 相同的哈希，
  字段不存在则不新增）。一处补齐，全部依赖 `_size` 的 Aura 方法立刻恢复。
- 效果：`lastIndexOf(2)` -1→**1**；`skip(1).size` 0→**2**；`tests/ArrayList`
  11 OK/9 FAIL → **14 OK/6 FAIL**。

**`tests/ArrayList` 剩余 6 个失败均为存量问题（与本轮改动无关）：**
- `test_addItem*.aura`(4) / `test_full.aura`：调用**已不存在的方法** `addItem` /
  `insert` → `未解析的函数调用`。
- `arraylist_basic.aura`：`ArrayList.unboxInt` 用 `(v as Long) >> 1`（**AOT 标签指针
  语义**），VM 下 `Value::Int(1)>>1 == 0` → `sum/min/max` 恒错。属 AOT/VM 值表示
  阻抗失配，独立议题。
