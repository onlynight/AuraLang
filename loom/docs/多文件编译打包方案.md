## 1. 现状分析：Aura 没有多文件编译机制

### 1.1 当前编译入口（代码事实）

```rust
// compiler/src/codegen/mod.rs
pub fn compile_source(source: &str) -> Result<BytecodeModule, String> {
    // 词法 → 语法 → 语义 → 字节码
    // 输入：一个字符串（单个 .aura 文件）
    // 输出：一个 BytecodeModule
}
```

**核心特征**：`&str` 单字符串输入 → 单模块输出。没有第二个入口函数接受多个文件。

### 1.2 关键缺口矩阵

| 维度 | C/C++ (Makefile) | C/C++ (CMake) | Java (Maven/Gradle) | Rust (Cargo) | Go (go.mod) | **Aura（当前）** |
|------|:----------------:|:-------------:|:-------------------:|:------------:|:----------:|:----------------:|
| 源文件列表 | `SRCS := a.c b.c` | `target_sources(tgt a.c b.c)` | `sourceSets.main.java.srcDirs` | `[lib] path = "src/lib.rs"` | 自动发现目录包 | **❌ 无** |
| 模块树 | 隐式（include + 对象文件） | 显式 target | `package` 声明 | `mod.rs` + 目录树 | 目录即包 | **❌ 无** |
| 依赖排序 | Make 规则依赖图 | CMake `add_dependencies` | classpath 顺序 | Cargo 递归解析 mod 树 | 自动发现 | **❌ 无** |
| 增量编译 | mtime 检查 | CMakeCache + ninja | Maven incremental | fingerprint | go build cache | **❌ 无** |
| 多输出产物 | 多 target | 多 target | jar/war/ear | lib/bin/cdylib | 单包 | **❌ 单 .auc** |
| 构建配置 | Makefile | CMakeLists.txt | pom.xml | Cargo.toml | go.mod | **⚠️ aura.toml（仅包元数据，无源文件字段）** |

### 1.3 现有 aura.toml 字段分析

```toml
# compiler/src/package.rs → PackageManifest
name = "..."           # 包名 ✅
version = "..."        # 版本 ✅
entry = "main.aura"    # 入口（单文件，非列表）⚠️
exports = [...]        # 导出符号名（字符串，非模块名）⚠️
library = false        # 库标记（Phase 1 新增）✅
kind = "bytecode"      # 包类型（Phase 1 新增）✅
dependencies = [...]   # 依赖声明 ✅
```

**缺口**：没有 `source-dirs` / `include` / `exclude` / `targets` 等字段，无法描述"哪些文件属于这个包"。

### 1.4 字节码层面的单模块约束

```rust
// compiler/src/vm/mod.rs
pub struct LoadedModule {
    pub funcs: Vec<DecodedFunction>,   // 只有本模块函数
    native_index: HashMap<String, u16>, // 原生函数按名字全局唯一
}

// compiler/src/vm/interp.rs
Instr::Call(idx) => self.do_call(top, idx as usize, false)?,
// Call(idx) 只能引用本模块内的函数索引
```

**无法跨模块调用**：`Call(idx)` 的 idx 是 `Vec<DecodedFunction>` 的下标，跨模块调用没有指令。

### 1.5 结论

> Aura 当前处于 **"单文件单模块"** 阶段——`aura build main.aura` 编译一个 `.aura` 文件产出一个 `.auc` 文件。
> 没有 Makefile/CMake/Cargo/tsconfig 任何类似的构建关联机制。
> 包格式方案（`.auz`）只覆盖了**制品分发**，未覆盖**源码编译**。

## 2. 对标设计：多文件编译机制

### 2.1 C/C++ — Makefile（规则依赖图）

```makefile
# Makefile 的本质：声明式规则 + 传递依赖
TARGET = app
SRCS = main.c utils.c math.c

$(TARGET): $(SRCS:.c=.o)
	$(CC) -o $@ $^

%.o: %.c
	$(CC) -c -o $@ $<

# 传递依赖：utils.o 依赖 utils.h，h 变了则 utils.o 也重编
utils.o: utils.c utils.h common.h
```

**核心思想**：
- **目标 → 前置条件 → 配方** 三元组
- **传递依赖**：`a.o: a.c` + `a.c: common.h` → `common.h` 变则 `a.o` 重编
- **自动推断**：`%.o: %.c` 是模式规则，自动匹配
- **增量编译**：mtime 比较，只重编变化的部分

### 2.2 C/C++ — CMake（声明式构建系统）

```cmake
# CMakeLists.txt
cmake_minimum_required(VERSION 3.20)
project(MyLib)

# 库目标：声明源文件列表
add_library(mylib STATIC
    src/core.c
    src/utils.c
    src/math.c
)

# 头文件搜索路径（类似 classpath）
target_include_directories(mylib PUBLIC
    ${CMAKE_CURRENT_SOURCE_DIR}/include
)

# 库依赖
target_link_libraries(mylib PRIVATE z)

# 可执行文件：声明源文件 + 链接库
add_executable(main
    app/main.c
)
target_link_libraries(main PRIVATE mylib)
```

**核心思想**：
- `add_library` / `add_executable` 声明**目标**
- 源文件列表**显式列出**
- `target_include_directories` 定义搜索路径
- `target_link_libraries` 定义库间依赖
- 生成平台特定构建系统（Makefile/Ninja/VS）

### 2.3 Java — Maven / Gradle（classpath + sourceSets）

```xml
<!-- pom.xml -->
<build>
  <sourceDirectory>src/main/java</sourceDirectory>
  <resources>
    <resource>
      <directory>src/main/resources</directory>
    </resource>
  </resources>
</build>

<!-- Gradle build.gradle -->
sourceSets {
    main {
        java { srcDirs = ['src/main/java'] }
        resources { srcDirs = ['src/main/resources'] }
    }
}
```

**核心思想**：
- `sourceSets.main.java.srcDirs` 定义**源码根目录**
- 编译器自动扫描目录下的 `.java` 文件
- `package` 声明决定类的全限定名（`com.example.Foo`）
- classpath 决定依赖顺序
- 所有 `.class` 打包到 `lib/*.jar`

### 2.4 Rust — Cargo.toml + mod 树（目录即模块）

```toml
# Cargo.toml
[lib]
path = "src/lib.rs"          # 库入口

[[bin]]
name = "mycli"
path = "src/main.rs"         # 可执行入口

# 或自动发现：src/lib.rs + src/bin/*.rs
```

```text
src/
├── lib.rs          # 库根：pub mod foo; pub mod bar;
├── foo.rs          # 模块 foo
├── bar/
│   ├── mod.rs      # 模块 bar 根
│   ├── baz.rs      # 子模块 bar::baz
│   └── qux.rs
└── main.rs         # 可执行入口
```

**核心思想**：
- **约定优于配置**：`src/lib.rs` 是库入口，`src/bin/*.rs` 是可执行入口
- **模块树**：`mod foo;` → 编译器查找 `src/foo.rs` 或 `src/foo/mod.rs`
- **递归编译**：Cargo 递归解析 mod 树，所有模块作为**单个 crate** 编译
- **单 crate 编译**：所有模块共享一个类型上下文，不需要跨模块链接

### 2.5 Go — go.mod + 目录包

```go
// go.mod
module github.com/user/project
go 1.21
require github.com/user/lib v1.0.0
```

```text
cmd/server/main.go      # 可执行包
pkg/utils/              # 库包（目录名 = 包名）
├── utils.go
└── helper.go
internal/core/          # 内部包（仅本模块可用）
```

**核心思想**：
- **目录即包**：每个目录是一个包，包名 = 目录名
- **自动发现**：`go build ./...` 扫描所有子目录
- **包级编译**：每个包独立编译，跨包通过 import 路径
- **无配置文件列出源文件**：完全靠目录结构

### 2.6 Node/TypeScript — tsconfig.json

```jsonc
{
  "compilerOptions": {
    "rootDir": "./src",
    "outDir": "./dist",
    "baseUrl": ".",
    "paths": {
      "@app/*": ["src/*"],       // 路径映射（类似 classpath）
      "@lib/*": ["lib/*"]
    }
  },
  "include": ["src/**/*.ts"],    // 源文件模式
  "exclude": ["node_modules"]
}
```

**核心思想**：
- `include` / `exclude` 定义源文件模式
- `paths` 映射 import 别名
- `outDir` 定义输出目录
- 所有 `.ts` 编译到 `.js`，保持目录结构

### 2.7 对比总结

| 特性 | Makefile | CMake | Maven/Gradle | Rust (Cargo) | Go | TS (tsconfig) | **Aura（建议）** |
|------|:--------:|:-----:|:------------:|:------------:|:--:|:-------------:|:----------------:|
| 源文件列表方式 | 显式列出 | 显式列出 | 目录扫描 | `mod.rs` 树 | 目录扫描 | glob 模式 | **混合（推荐）** |
| 模块树 | 隐式 | 显式 target | `package` 声明 | 约定 mod.rs | 目录即包 | paths 映射 | **显式 + 约定** |
| 单 crate / 多包 | 多 target | 多 target | 多 jar | 单 crate | 多包 | 多 JS | **多模块（.auz）** |
| 增量编译 | mtime | mtime | mtime | fingerprint | go cache | tsc cache | **fingerprint + mtime** |
| 依赖排序 | 规则依赖 | target 依赖 | classpath | 递归 mod | import 图 | import 图 | **import 图** |
| 配置格式 | Makefile | CMakeLists.txt | pom.xml / .gradle | Cargo.toml | go.mod | tsconfig.json | **aura.toml（扩展）** |

## 3. Aura 多文件编译方案设计

### 3.1 设计原则

1. **单一配置源**：复用现有 `aura.toml`，新增 `[build]` 表，不引入新文件
2. **约定优于配置**：目录结构提供默认行为，配置可覆盖
3. **多模块字节码**：每个源文件 → 一个 `.auc` 模块，不是合并为一个大文件
4. **编译期链接 + 运行期加载**：编译期解析符号引用，运行期按需加载模块
5. **增量编译**：fingerprint 缓存，只重编变化的模块
6. **与 `.auz` 对齐**：多文件编译产物直接填入 `.auz` 的 `lib/` 和 `ref/` 目录

### 3.2 项目目录结构（约定）

```text
my-project/
├── aura.toml              # 项目配置（含 [build] 表）
├── aura.lock              # 依赖锁
├── src/                   # 源码目录（默认）
│   ├── main.aura          # 入口文件（entry 指向）
│   ├── utils.aura         # 模块：工具函数
│   ├── math/              # 子目录 = 子模块
│   │   ├── mod.aura       # 子模块根（约定：mod.aura，类似 Rust mod.rs）
│   │   ├── vector.aura    # 子模块 vector
│   │   └── matrix.aura    # 子模块 matrix
│   └── net/
│       └── mod.aura       # 子模块 net
├── resources/             # 非代码资源（可选）
│   └── config.json
├── test/                  # 测试（可选）
│   └── utils_test.aura
└── vendor/                # 本地依赖（可选）
    └── aura-json/         # Git clone 或 .auz 展开
```

**约定规则**：
| 路径 | 含义 | 来源 |
|------|------|------|
| `src/` | 源码根目录 | 默认值，`[build] source-dirs` 可覆盖 |
| `src/main.aura` | 入口文件 | `entry` 字段 |
| `src/<name>.aura` | 顶层模块 | 自动发现 |
| `src/<dir>/mod.aura` | 子模块根 | 自动发现（类 Rust mod.rs） |
| `src/<dir>/<name>.aura` | 子模块子文件 | 自动发现 |
| `test/` | 测试文件 | 默认值 |

### 3.3 模块树定义（三种方式）

#### 方式 A：自动发现（推荐，默认）

编译器扫描 `src/` 目录，按目录结构自动构建模块树：

```text
src/main.aura          → module: "main"
src/utils.aura         → module: "utils"
src/math/mod.aura      → module: "math"
src/math/vector.aura   → module: "math.vector"
src/math/matrix.aura   → module: "math.matrix"
src/net/mod.aura       → module: "net"
```

**模块名规则**：
- 文件名（不含扩展名）= 模块名
- 目录前缀 + 模块名 = 全路径名（`math.vector`）
- `mod.aura` 是目录模块的根（类似 Rust `mod.rs`）

#### 方式 B：显式声明（在 aura.toml 中）

```toml
[build]
source-dirs = ["src", "lib"]           # 多个源码目录

# 显式列出模块（覆盖自动发现）
modules = [
  { name = "main",    path = "src/main.aura" },
  { name = "utils",   path = "src/utils.aura" },
  { name = "math",    path = "src/math/mod.aura", children = ["vector", "matrix"] },
  { name = "math.vector",  path = "src/math/vector.aura" },
  { name = "math.matrix",  path = "src/math/matrix.aura" },
]
```

#### 方式 C：include/exclude 模式（类 TypeScript）

```toml
[build]
source-dirs = ["src"]
include = ["**/*.aura"]          # 包含模式
exclude = [
  "**/*.test.aura",             # 排除测试
  "**/vendor/**",               # 排除第三方
  "src/main.aura",              # 排除入口（单独处理）
]
```

**推荐**：方式 A（自动发现）+ 方式 C（include/exclude 微调）。

### 3.4 import 解析与依赖图

#### 3.4.1 import 语法扩展

```aura
// 导入标准库（现有行为）
import aura.math.sin
import aura.io.*

// 导入项目内模块（新增）
import math.vector              // 解析为 src/math/vector.aura
import math.vector.Vector       // 解析为 src/math/vector.aura 中的 Vector
import utils                    // 解析为 src/utils.aura
import net                      // 解析为 src/net/mod.aura

// 导入第三方库（已有，P11）
import "aura-json" as json      // 从 .auz 或 Git 解析

// 导入带别名
import math.vector as vec       // vec.Vector 等价于 math.vector.Vector
```

#### 3.4.2 解析优先级

```text
1. 标准库：aura.<module>.*  → 内置 std 模块
2. 本地模块：module.path    → 从 src/ 目录树解析
3. 二进制依赖：import "pkg" → 从 .auz 解析（P11 包格式方案 §11）
4. 源码依赖：import from path → 从路径加载（已有 DependencySource::Path）
```

#### 3.4.3 依赖图构建

```text
解析所有 .aura 文件 → 提取 import 声明 → 构建有向图

main.aura
├── imports utils
│   └── imports math.vector
│       └── imports math.matrix
└── imports net
    └── imports aura-json (binary)
```

**拓扑排序**：按依赖图排序，被依赖的模块先编译。

### 3.5 编译流水线

```text
1. 源码发现
   └── 扫描 src/ → 模块列表 + 模块名

2. import 解析
   └── 解析所有 import → 构建依赖图
   └── 拓扑排序 → 编译顺序

3. 增量检查
   └── 比较 fingerprint（源文件哈希 + 依赖哈希）
   └── 标记需要重编的模块

4. 逐模块编译
   for module in topological_order:
     ├── 词法 → 语法 → AST
     ├── 语义检查（含跨模块类型检查）
     ├── HIR → MIR → 字节码
     ├── 写入 lib/<module_name>.auc
     └── 生成 ref/<module_name>.sig（类型签名，Phase 3）

5. 链接器
   └── 扫描所有 .auc 的导出/导入符号
   └── 验证符号引用一致性
   └── 冲突检测
   └── 生成 lib/index.json（模块索引）

6. 打包（可选）
   └── .auz = tar + zstd（包格式方案 §5）
```

### 3.6 多模块字节码格式

#### 3.6.1 模块标识

每个 `.auc` 文件需要携带模块身份信息：

```text
"AURA"       魔数
u16          version = 2              # 递增到 2（新增模块字段）
u16          header_flags             # 位掩码
u16          module_name_len + name   # 如 "math.vector"
u16          module_uuid_len + uuid   # 如 "aura-math:0.3.0"
u32          module_id                # 在模块树中的唯一索引
```

#### 3.6.2 跨模块调用指令

在现有 `Call(idx)` 基础上增加：

| 指令 | 操作数 | 语义 |
|------|--------|------|
| `Call(idx)` | u16 | 调用本模块函数（现有，保留） |
| `CallModule(mod_idx, sym_idx)` | u16 + u16 | 调用模块树中的模块（编译期解析） |
| `CallExternal(mod_uuid, sym_idx)` | 字符串 + u16 | 调用外部库模块（运行期解析） |

**`CallModule` 解析流程**：
```text
1. mod_idx → ModuleRegistry.modules[mod_idx]
2. sym_idx → module.exports[sym_idx].function_idx
3. 调用目标函数
```

#### 3.6.3 模块索引（lib/index.json）

```json
{
  "version": 2,
  "compiler_version": "0.3.0",
  "modules": [
    {
      "name": "main",
      "path": "lib/main.auc",
      "id": 0,
      "exports": ["main"],
      "imports": ["utils", "net"],
      "has_entry": true
    },
    {
      "name": "utils",
      "path": "lib/utils.auc",
      "id": 1,
      "exports": ["clamp", "lerp"],
      "imports": ["math.vector"],
      "has_entry": false
    },
    {
      "name": "math.vector",
      "path": "lib/math/vector.auc",
      "id": 2,
      "exports": ["Vector", "dot", "cross"],
      "imports": [],
      "has_entry": false
    }
  ]
}
```

### 3.7 aura.toml [build] 扩展

```toml
# ── 项目基础信息（现有） ──
name = "my-app"
version = "1.0.0"
entry = "src/main.aura"          # 入口文件（相对路径）

# ── 构建配置（新增 [build] 表） ──
[build]
# 源码目录（类 Java sourceSets / Rust src/）
source-dirs = ["src"]            # 默认 ["src"]，可多个

# 包含/排除模式（类 TypeScript include/exclude）
include = ["**/*.aura"]          # 默认 ["**/*.aura"]
exclude = [
  "**/*.test.aura",
  "vendor/**",
  "target/**",
]

# 编译模式
mode = "incremental"             # incremental | full | clean
                                  #   incremental = 增量编译（默认）
                                  #   full         = 全量编译
                                  #   clean        = 清理后重编

# 优化级别
opt-level = 2                    # 0/1/2/3

# 目标三元组（AOT 时用）
target = "x86_64-pc-windows-msvc"

# 输出目录
out-dir = "target/build"         # 默认 "target/build"

# 是否生成类型签名（Phase 3）
emit-signatures = true

# 是否打包为 .auz
emit-package = false             # false = 仅字节码，true = 打包 .auz

# 模块别名映射（类似 tsconfig paths）
[build.alias]
"@app" = "src"
"@lib" = "lib"
```

### 3.8 增量编译

#### 3.8.1 Fingerprint 机制

```text
fingerprint(module) = SHA256(
  源文件内容哈希
  + 依赖模块的 fingerprint 哈希
  + 编译器版本
  + 编译选项（opt-level, target, features）
)
```

#### 3.8.2 缓存目录

```text
target/
├── build/
│   ├── lib/                    # 编译产物
│   │   ├── main.auc
│   │   ├── utils.auc
│   │   └── math/vector.auc
│   └── index.json              # 模块索引
└── cache/
    ├── fingerprints.json       # 模块指纹缓存
    └── artifacts/              # 编译中间产物（可选）
        └── main.hir/           # HIR dump（调试用）
```

#### 3.8.3 增量检查流程

```text
for module in topological_order:
  current_fp = compute_fingerprint(module)
  cached_fp = fingerprints.json[module.name]
  
  if current_fp == cached_fp:
    skip（模块未变化，跳过编译）
  else:
    compile(module)
    fingerprints.json[module.name] = current_fp
```

### 3.9 ModuleRegistry（运行期）

对应包格式方案 §8.1，补齐实现：

```rust
// compiler/src/vm/module_registry.rs

pub struct ModuleRegistry {
    /// 已加载模块，按 module_id 索引
    modules: HashMap<u32, LoadedModule>,
    /// 模块名 → module_id
    name_index: HashMap<String, u32>,
    /// 符号表：(module_id, symbol_name) → (module_id, function_idx)
    symbol_table: HashMap<(u32, String), (u32, u16)>,
    /// 原生函数：按命名空间 "{module_name}.{name}" 隔离
    native_table: HashMap<String, NativeFn>,
}

impl ModuleRegistry {
    /// 从 .auz 或 lib/ 目录加载模块
    pub fn load_from_directory(&mut self, dir: &Path) -> Result<(), VmError>;
    
    /// 从单个 .auc 文件加载模块
    pub fn load_module(&mut self, path: &Path) -> Result<u32, VmError>;
    
    /// 解析符号引用：(module_id, symbol_name) → 可调用目标
    pub fn resolve(&self, module: u32, symbol: &str) -> Option<CallTarget>;
}
```

## 6. 风险与待解决问题

| # | 问题 | 影响 | 缓解 |
|---|------|------|------|
| R1 | 循环依赖检测 | 编译期死锁或链接错误 | 拓扑排序时检测环，报错提示 |
| R2 | 模块名冲突 | 两个目录都有 `utils.aura` | 模块名 = 全路径（`src.a.utils`），禁止重名 |
| R3 | 增量编译缓存失效 | 漏编或重复编 | fingerprint 包含依赖链哈希，级联失效 |
| R4 | 大项目编译速度 | 百模块以上增量编译慢 | 并行编译（模块间无共享状态），fingerprint 预过滤 |
| R5 | import 解析歧义 | `import utils` 指向多个模块 | 按目录深度优先（近邻优先），歧义报错 |
| R6 | 向后兼容单文件模式 | 现有用户脚本失效 | 保留 `--single` 参数，`compile_source` 不变 |
| R7 | 与包格式方案 Phase 2 的协调 | 两个 Phase 并行开发 | 接口契约先行（`.auc` 格式 + `ModuleRegistry` API） |

## 7. 附录：与其他语言的细节对照

### 7.1 Makefile vs aura.toml

| 维度 | Makefile | aura.toml `[build]` |
|------|----------|---------------------|
| 目标 | `TARGET = app` | `entry = "src/main.aura"` |
| 源文件 | `SRCS = a.c b.c` | `include = ["**/*.aura"]` |
| 前置条件 | `$(TARGET): $(SRCS)` | 依赖图（import 解析） |
| 配方 | `$(CC) -o $@ $^` | 编译器内置流水线 |
| 增量 | mtime 检查 | fingerprint 哈希 |
| 变量 | `CC = gcc` | `[build] target = "..."` |

### 7.2 CMake vs aura.toml

| 维度 | CMake | aura.toml |
|------|-------|-----------|
| 库声明 | `add_library(mylib src/*.c)` | `library = true` + `[build]` |
| 可执行 | `add_executable(main app/main.c)` | `entry = "src/main.aura"` |
| 头文件路径 | `target_include_directories` | `[build.alias]` |
| 库依赖 | `target_link_libraries` | `[dependencies]` |
| 生成器 | 平台特定（Ninja/Make/VS） | 单一后端（Aura VM） |

### 7.3 Cargo vs aura.toml

| 维度 | Cargo.toml | aura.toml |
|------|-----------|-----------|
| 库入口 | `[lib] path = "src/lib.rs"` | `[build] source-dirs = ["src"]` + `entry` |
| 可执行 | `[[bin]] path = "src/main.rs"` | 多入口（`entry` 可为数组） |
| 模块树 | `mod.rs` + 目录约定 | `mod.aura` + 目录约定 |
| 依赖 | `[dependencies]` | `[dependencies]` |
| 特性门控 | `[features]` | `[build] features`（待定） |
| 发布 | `cargo publish` | `aura publish` |

### 7.4 tsconfig.json vs aura.toml

| 维度 | tsconfig.json | aura.toml `[build]` |
|------|--------------|---------------------|
| 源码目录 | `rootDir` | `source-dirs` |
| 输出目录 | `outDir` | `out-dir` |
| 包含模式 | `include` | `include` |
| 排除模式 | `exclude` | `exclude` |
| 路径映射 | `paths` | `[build.alias]` |
| 编译选项 | `compilerOptions` | `[build]` 表 |

## 8. 附录：关键设计决策

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| D1 | 配置格式 | 扩展 `aura.toml`（新增 `[build]` 表） | 单一配置源，不引入新文件 |
| D2 | 源文件发现 | 目录扫描 + include/exclude | 类 TypeScript，减少手工维护 |
| D3 | 模块树约定 | `mod.aura` 文件 | 类 Rust mod.rs，开发者熟悉 |
| D4 | 编译产物 | 每文件一个 `.auc` | 支持增量编译，不合并为单文件 |
| D5 | 跨模块调用 | `CallModule(mod_idx, sym_idx)` | 索引方案，O(1) 解析，抗混淆 |
| D6 | 增量编译 | fingerprint 哈希 | 比 mtime 可靠，支持并行编译 |
| D7 | 单文件兼容 | `--single` 参数 | 保留现有行为，平滑迁移 |
| D8 | 依赖排序 | 拓扑排序 | 类 Rust/Go，编译期确定顺序 |
| D9 | 与 .auz 关系 | 本文档是前置，.auz 是打包 | 多文件编译 → 多模块 .auc → .auz 打包 |
| D10 | 运行期加载 | `ModuleRegistry` + lazy load | 类 Java 类加载器，节省启动时间 |
