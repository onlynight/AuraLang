# loom 默认配置合并设计

> 目标：让 `aura.toml` 只写"与默认不同的字段"，减少 80%+ 的样板配置。

---

## 1. 背景与问题

### 1.1 现状

当前 loom 的 `LoomManifest` 结构体（`src/manifest/mod.rs`）大量使用 `#[serde(default)]` 和 `#[serde(default = "default_xxx")]`，但存在三个问题：

| 问题 | 现象 | 根因 |
|---|---|---|
| **P1 配置冗长** | `examples/hello/aura.toml` 86 行、`ext_ffi_demo/aura.toml` 91 行，大量字段写的是默认值 | serde 只处理标量字段默认；嵌套表（`[build.source-sets.main]`）一旦项目只写部分字段，整个表被替换，丢失结构默认 |
| **P2 强制文件** | `load_and_execute` / `CheckConfig` 在 `aura.toml` 不存在时直接 `bail!` | 无内置默认兜底 |
| **P3 默认值分散** | 默认值散落在 `mod.rs` 的 `default_xxx()` 函数里，用户看不到 | 默认值没有单一权威源 |

### 1.2 目标

1. 编译时嵌入一份默认 `aura.toml`，作为单一权威源。
2. 项目 `aura.toml` 在 TOML 值级别**深度合并**覆盖默认值。
3. 缺失 `aura.toml` 的目录不再报错，回退到默认配置。
4. `loom new` 生成最小 aura.toml（仅 name/version/description）。

---

## 2. 设计

### 2.1 优先级链

```
CLI 参数  >  激活 Profile  >  项目 aura.toml  >  内置默认 aura.toml  >  serde 字段级默认
   (1)           (2)               (3)                 (4)                   (5)
```

- **(1) CLI**：`--opt-level`、`--debug`、`--profile` 等，由 `priority.rs::CliOverrides` 处理。
- **(2) Profile**：`--profile release` 激活后覆盖 build 字段。
- **(3) 项目**：用户编写的 `aura.toml`。
- **(4) 内置默认**：编译时嵌入的 `default.toml`（新增）。
- **(5) serde**：`#[serde(default)]` 字段级兜底（已有）。

### 2.2 文件布局

```
loom/src/manifest/
├── mod.rs          # 现有：LoomManifest 结构体 + serde 默认（不动）
├── default.toml    # 新增：内置默认配置（include_str! 嵌入）
├── default.rs      # 新增：DEFAULT_TOML + merge() + default_value()
├── parse.rs        # 改：合并逻辑
├── validate.rs     # 不变
└── priority.rs     # 不变
```

### 2.3 内置默认 `default.toml`

只声明 **serde 无法处理的结构性默认**（嵌套表、有语义的占位值）：

```toml
schema-version = "2.0"
name = "unnamed"
version = "0.1.0"

# 源码集（嵌套表，serde 无法给 HashMap 提供模板默认）
[build.source-sets.main]
source-dirs = ["src"]
resource-dirs = ["resources"]
include = ["**/*.aura"]
exclude = ["**/*.test.aura", "vendor/**", "target/**"]
depends-on = []

[build.source-sets.test]
source-dirs = ["test"]
resource-dirs = ["test/resources"]
include = ["**/*.aura"]
exclude = []
depends-on = ["main"]

# Profile 预设（activate 默认 false，由用户/CLI 激活）
[profiles.release]
activate = false
[profiles.release.build]
opt-level = 3
debug = false
emit-package = true

[profiles.debug]
activate = false

# 默认仓库
[repositories]
central = "https://registry.aura-lang.dev"
```

**为什么不需要写其他字段**：

| 字段类型 | 示例 | 处理方 |
|---|---|---|
| 标量（有语义默认） | `opt-level = 2`、`debug = true`、`entry = "src/main.aura"` | serde `#[serde(default = "default_xxx")]` |
| 空数组 | `dependencies = []`、`exports = []` | serde `#[serde(default)]` |
| 空表 | `alias = {}`、`plugins.external = {}` | serde `#[serde(default)]` |
| `Option<T>` 缺失 | `target = None`、`compiler-min-version = None` | serde `#[serde(default)]` |

内置 `default.toml` 只需补齐 serde 处理不了的嵌套表默认值。

### 2.4 合并语义

`merge(base, overlay)` 在 `toml::Value` 级别递归：

| base | overlay | 结果 |
|---|---|---|
| Table | Table | 递归合并：overlay 的 key 覆盖 base 同名 key；base 独有的 key 保留 |
| Table | 非 Table | overlay 整体替换 |
| 非 Table | Table | overlay 整体替换 |
| Array | Array | **overlay 整体替换**（不做元素级合并，避免语义歧义） |
| 标量 | 任意 | overlay 整体替换 |

### 2.5 合并场景验证

#### 场景 A：项目只写 `exclude`

```toml
[build.source-sets.main]
exclude = ["foo"]
```

合并后：
```
source-dirs = ["src"]            # 默认
resource-dirs = ["resources"]    # 默认
include = ["**/*.aura"]          # 默认
exclude = ["foo"]                # 项目覆盖
depends-on = []                  # 默认
```

✓ 用户只写 1 个字段，其他字段自动继承默认。

#### 场景 B：项目只写 `[build] opt-level`

```toml
[build]
opt-level = 0
```

合并后：
```
opt-level = 0                    # 项目
debug = true                     # serde 默认
out-dir = "target/build"         # serde 默认
source-sets.main = {...}         # 内置默认
```

✓ `[build]` 表内未指定的字段走 serde 默认。

#### 场景 C：项目写 `[profiles.release.build] opt-level`

```toml
[profiles.release.build]
opt-level = 1
```

合并后：
```
profiles.release.activate = false      # 默认
profiles.release.build.opt-level = 1   # 项目
profiles.release.build.debug = false   # 默认
profiles.release.build.emit-package = true  # 默认
```

✓ Profile 嵌套表的逐字段覆盖。

#### 场景 D：项目省略 `[build.source-sets.test]`

合并后：test 源码集完整保留（来自内置默认）。✓

#### 场景 E：项目省略 `[repositories]`

合并后：`central = "https://registry.aura-lang.dev"`（来自内置默认）。✓

## 3. API 变化

### 3.1 `parse.rs`（行为变化）

```rust
// 新增：从 Value 合并解析（内部）
pub fn parse_merged(project_value: toml::Value) -> Result<LoomManifest, LoomError>

// 行为变化：文件不存在时返回默认 Manifest（不再 bail）
pub fn parse_from_file(path: &Path) -> Result<LoomManifest, LoomError>

// 行为变化：合并默认后解析
pub fn parse_from_str(s: &str) -> Result<LoomManifest, LoomError>

// 不变
pub fn parse_and_validate(path: &Path) -> Result<LoomManifest, LoomError>

// 重写：基于内置默认，只覆盖 name/version/description/repo/exports
pub fn default_manifest(name: &str) -> LoomManifest
```

### 3.2 `default.rs`（新增）

```rust
pub const DEFAULT_TOML: &str = include_str!("default.toml");
pub fn default_value() -> toml::Value;
pub fn default_manifest() -> LoomManifest;
pub fn merge(base: toml::Value, overlay: toml::Value) -> toml::Value;
```

### 3.3 `main.rs`（软化缺失文件）

| 命令 | 当前行为 | 新行为 |
|---|---|---|
| `loom build/compile/test/run/watch` | 无 `aura.toml` → `bail!` | 无文件 → 用默认 + 提示 |
| `loom check-config` | 无文件 → `bail!` | 无文件 → 检查合并结果 + 提示 |
| `loom check` | 无文件 → skip | 不变 |
| `loom ide` | 无文件 → `Err` | **保持 Err**（IDE 必须指向真实项目） |
| `loom new` | 写完整 TOML | **写最小 TOML**（仅 name/version/description） |

## 4. 影响范围

### 4.1 不改的

- `LoomManifest` 结构体与 serde 默认函数（`mod.rs`）— 保持现状，作为"最后兜底"。
- `validate.rs` — 校验逻辑不变，合并后 Manifest 自然通过。
- `priority.rs`（CLI/Profile 覆盖）— 不变，仍是最高优先级。
- `workspace/members.rs` — 成员 aura.toml 解析自动走新逻辑（无需改代码）。
- 所有示例项目 aura.toml — 兼容旧格式，新旧都能用。

### 4.2 改的

| 文件 | 改动 |
|---|---|
| `src/manifest/default.toml` | 新增 |
| `src/manifest/default.rs` | 新增 |
| `src/manifest/mod.rs` | +1 行 `pub mod default;` |
| `src/manifest/parse.rs` | 重写合并逻辑 |
| `src/main.rs` | 软化缺失文件 + `loom new` 最小化 |
| `src/lib.rs` | +1 行导出 `default` 模块 |
| `examples/hello/aura.toml` | 更新为最小风格（演示新用法） |
| `loom/README.md` | 新增"配置优先级"章节 |

## 5. 兼容性与边界

| 场景 | 行为 |
|---|---|
| 老项目（完整 aura.toml） | 完全兼容，合并是幂等的（项目值 = 默认值时结果不变） |
| 新项目（最小 aura.toml，仅 name/version） | 所有默认自动生效 |
| 无 aura.toml 目录 | `build/check-config` 用默认 + 提示；`ide` 仍报错 |
| 项目显式写 `name = ""` | 合并后 name = ""，`validate_manifest` 报错（保留严格性） |
| 项目省略 `name` | 合并后 name = "unnamed"（占位），validation 通过但语义上应提示 |
| Profile 激活冲突 | 默认两 profile 都是 `activate = false`，冲突不会发生 |
| Workspace 根配置 `entry = ""` | 项目显式覆盖默认 `entry = "src/main.aura"`，validation 通过（library 模式不要求 entry） |

## 7. 关键决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| `parse_from_str` 是否合并默认？ | 合并 | 统一行为；库内无调用者（grep 确认），仅 `lib.rs` 导出；外部调用者如依赖纯解析，可用 `toml::from_str` |
| `loom new` 是否写最小 TOML？ | 是 | 新用户体验更好，与内置默认配合 |
| 示例 aura.toml 是否更新？ | 仅 `hello/` | 其余保留作为完整参考 |
| 数组合并语义 | 整体替换 | 避免元素级合并的语义歧义（如 `dependencies` 数组的"合并"无明确定义） |
| Profile `activate` 默认值 | `false` | 避免默认两个 profile 都 activate 触发 validation 错误 |
